## 5. 阻断发布的连续性问题

### P0-1：决定性证据没有唯一来源链

同一核心交易证据至少出现了四种版本：举报者日记中夹着转账复印件、苏婉誊写的名单和账目、沈默遗物封皮夹层里的原始协议、沈默妻子整理遗物时交出的记录。第 15、18、19 章分别调用不同来源，却没有说明它们是互相印证的不同证据，也没有建立保管、复制、送检和公开的时间线。

结果不是“小瑕疵”，而是悬疑小说的证明责任崩溃：读者无法判断哪份是真正的决定性物证、谁有接触权限、赵明远和林默各自知道什么。

### P0-2：赵明远的主体身份被污染

Cast 将赵明远写成“政客王建国的助理”，对王建国怀恨；正文却始终把他写成周启明的助理，并把复仇、匿名信、沈默遗物、河桥男尸全部绑定到周启明。`subject-5` 这个 ID 在结构上合法，所以现有 ID 校验无法发现同一主体内部的雇主和仇恨对象已经换人。

第 10 章举报者说沈默是叔叔，第 17 章赵明远又以父亲之死解释复仇；匿名信先被说成模仿沈默笔迹，后又与档案室来信同笔迹，而那封信又被说明为赵父所写。理论上可以通过“赵明远同时拥有两位受害亲属并故意仿写”补救，但正文没有给出这条解释，因此读者实际接收到的是三套互相竞争的身份来源。

### P0-3：高潮人质是纯功能性临时道具

第 17 章年轻人质此前没有设置、没有姓名、没有与赵明远或周启明的关系、没有赵明远杀他的理由，获救后也不再出现。所谓“最终预言”和“阻止谋杀”因此不是前 16 章因果链的兑现，而是为了满足 Spine 的 climax 句子临时生成了一个待救对象。

### P0-4：第 15 和第 18 章重复同一戏剧任务

两章都是“林默在发布会上展示交易证据 -> 律师/周启明否认并威胁 -> 媒体哗然 -> 警方介入 -> 林默面临诉讼”。第 18 章 Detail handoff 甚至直接重复第 15 章 handoff。现有 Detail preflight 只在**相邻章节**且签名或标题/目的近乎完全一致时识别重复，无法发现隔两章的语义复演。

### P0-5：前半部主线资产没有回收

- 深蓝旧纽扣后来变成银色纽扣形胸针，且没有进入高潮证明链。
- 老式相机、地下室门、水塔埋物和“第七页”便签没有形成明确回收。
- 周维作为关键失踪者出现后消失，失踪案没有闭环。
- 苏婉“中途失联”的 Cast 职责没有被清楚戏剧化和解释。
- 林默的抄袭丑闻只作为反派施压按钮，没有回答是否属实、为何发生、主人公承担什么责任。

### P1-1：主人公不是在推理，而是在接收材料

匿名信、旧档案、便签、日记、转账复印件、名单、协议、口供轮番主动送到林默面前。林默的记者能力主要表现为“看材料、找陈国栋确认、决定继续查”，没有形成“观察 -> 假设 -> 验证 -> 排除 -> 新选择”的可复盘推理链。悬疑公平性因此较弱。

### P1-2：程序现实性不足

银行内部账户经熟人电话查询、警方内部材料被多次私下转交、嫌疑人口供和未终结鉴定被直接拿到发布会公开、警方在“非正式夜巡”中调便衣包围现场，均缺少足够的程序代价。Brief 明确要求“警方和媒体反应影响行动空间”，正文却通常让程序只在对话里阻拦，随后立即为情节让路。

### P1-3：结局代价是预设执行，不是人物弧自然完成

“放弃写作、与陈国栋和苏婉决裂”从 Brief ending promise 到 Cast change、Volumes closure、Detail 终章都被逐层复制。正文只需要把人物送到预定终点，却没有充分建立林默为何把赵明远的犯罪、自己泄露证词的责任和“虚构本身不可信”画上等号。第 20 章文句有余韵，但心理结论缺少足够中间台阶。

## 6. 文风与可读性问题

全文局部语言比因果结构成熟，但存在明显模板化动作复用。粗略统计：

- “沉默”27 次
- “没有说话”12 次
- “没有回答”9 次
- “停了一下”9 次
- “看了……秒”类动作15 次
- “指节泛白”4 次

这些表达单独看没有问题，但集中出现后，人物共享同一套反应词库：看、停、沉默、手指收紧、指节泛白、声音压低。陈国栋、苏婉、周启明、赵明远的对白措辞和身体反应区分度不足，Cast 中已经冻结的 `temperament`、`speech_style` 没有被稳定演绎。

此外，第 11 章存在明显的引号嵌套错误；第 16 章存在整句段重复。这说明 prose reviewer 还缺少确定性的排版、重复片段和标点检查。

## 8. 为什么现有 Prompt 写得很严，结果仍然失控

当前 Prompt 已明确要求：不得新增未注册人物、不得新增文书和权限、不得重复上一章、必须承接 Story State、Detail 道具必须回收。这些方向是对的，问题在于系统把它们大多留在自然语言要求里。

真正具有硬阻断力的代码目前主要检查：

1. JSON/schema 形状、ID、数量和顺序。
2. Detail 中显式填写的 `cast_ids` 是否存在。
3. 少数可正则识别的世界时间规则。
4. 正文中新出现的数字、日期、序号等量化事实。
5. 单章最低长度等确定性结构合同。

而本书真正失败的约束是语义性的：赵明远到底服务谁、协议从哪里来、人质是谁、第 15 和第 18 章是否做了同一件事、纽扣是否还是同一物件。这些没有稳定 ID、属性和生命周期，代码便无法确定性比较；Reviewer 又只有局部上下文且没有门禁权，于是“Prompt 违反”最终只表现为被忽略的 warning，甚至完全漏检。

## 9. 整体流程是否符合真实小说创作流程

### 9.1 阶段顺序基本合理

`brief -> spine -> cast -> volumes -> detail -> text -> cover -> export` 与真实类型小说生产的宏观顺序相容：先立项和承诺，再构建因果骨架、人物圣经、卷章架构、章节施工图，最后写正文和出版物。这一顺序不需要推翻。

### 9.2 当前执行方式不符合真实成稿流程

真实创作不是每个上游阶段“一稿 schema 合法便冻结”，也不是每章写完只看前一章便自动接受。至少还需要三类编辑循环：

1. **谜底反推循环**：悬疑题材应先冻结真相、凶手目标、受害者、作案机制、证据来源、误导和最终证明，再反推投放顺序。
2. **跨 Artifact 连读循环**：Spine、Cast、Volumes、Detail 冻结前，应检查同一人物、地点、物件、证据和责任在各阶段是否同一。
3. **滚动与全稿编辑循环**：正文既要做单章语言审校，也要做 3-5 章滚动连续性、分卷审读和全书冷读；后者完成前不能进入发布验收。

因此，当前流程是“生产运行时合理，编辑闭环不足”。八阶段可以保留，但需要在同一权威路径内补足确定性投影和阶段门，不应再增加另一套 runtime 或隐藏重写路径。

## 10. 建议的目标生产闭环

### P0：先修止损门

1. Fast 自动接受章节前，`required_review_unavailable` 必须进入明确的 `needs_action`，不能静默接受；不要求无限重试。
2. Reviewer finding 继续只作为模型证据，不能凭自报 severity 自动硬阻断；但可确定化的 `subject_identity_conflict`、`evidence_provenance_conflict`、`detail_duplicate_job` 应由代码生成 blocker。
3. Fast 上游阶段不能只凭 schema 合法自动接受：Brief、Cast、Detail 至少要跑完确定性跨 Artifact preflight。
4. Text 完成后、Cover 前增加同一 Run 内的全书终检决策：确定性冲突可阻断，文学判断只给作者 warning，绝不隐藏循环换稿。

### P0：给悬疑故事建立可执行的真相与线索账本

在 Spine/Detail 之间生成代码拥有 ID 的只读投影，不建立第二权威 Artifact：

- `truth_id`：最终真相命题
- `actor_id` / `victim_id`：行动者与受害者
- `clue_id`：纽扣、相机、日记、转账、协议等稳定线索
- `source_owner`：谁创建、持有、转交
- `state`：setup / misdirected / reinterpreted / verified / paid_off
- `chapter_refs`：投放、转义、验证、回收章节
- `proves_or_refutes`：它证明或排除什么

任何决定性证据改变来源、具名道具没有回收、高潮受害者没有前置责任时，Detail 不得提交。

### P0：强化主体唯一性

1. Cast 对所有可持续影响因果的自然人使用唯一 `subject_id`；周维和高潮人质要么注册并承担职责，要么从剧情删除。
2. 对角色档案中的具名实体做引用绑定，不能只把“王建国/周启明”留在自由文本里。
3. 校验 `debut` 不只是“最早允许”，还要有首次有效出场回执；赵明远不能到第 17 章才被主人公无来源地直接认出。
4. Detail scene 的现场行动者必须可投影到 `cast_ids`；纯机构或无名群众可以是受控的临时 role，但不能承担主线证据、受害或反转职责。

### P1：升级连续性上下文与审稿窗口

1. 生成仍保持有界上下文，不输入全文；但 Story State 应增加地点、物件、证据 provenance、人物知识和未决线索投影。
2. 单章 continuity review 除上一章全文外，读取最近 3-5 章的结构化事件摘要和所有相关未决线索，而不是只按当前 `cast_ids` 截取人物状态。
3. 每 5 章做一次滚动审读，检查重复任务、时间、知识、证据来源、关系弧和伏笔；只生成证据和修订建议，不自动重写历史 accepted 章。
4. 终稿做一次全书批次审读，输出问题定位后由作者决定从哪个 checkpoint 创建新分支修订。

### P1：补足现实程序和人物责任

1. Brief 的世界规则不要写“每个居民都相关”这类不可执行口号；应冻结媒体核验、警方权限、证据公开和法律风险的最小现实规则。
2. Detail 中每一次银行查询、警方材料调用、鉴定、发布会公开都要写清权限、耗时、代价和责任承担者。
3. 林默的抄袭事实必须明确真假；如果属实，它应成为人物弧的一部分，而不只是反派按钮。
4. “放弃写作”应由一串可见选择导致，例如错误公开、伤害证人、误判匿名信、发现自身作品被利用，而不是只在终章按 ending promise 执行。

### P2：文风与排版终检

增加不依赖模型的重复片段、引号配对、连续段落重复、常用动作簇统计；Prose reviewer 再处理人物声音区分、解释性心理和比喻密度。确定性排版错误可以阻断，风格偏好只提示作者。

## 11. 下一轮真实 Run 的验收标准

1. Brief 标题是真实书名，不是题材或模式标签；世界规则与最终解释不冲突。
2. Cast 中所有持续因果主体的身份、雇主、亲属和 debut 唯一且可追踪。
3. 核心谜底在写正文前拥有完整的“真相 -> 线索 -> 误导 -> 验证 -> 回收”链。
4. 所有关键物证拥有唯一 provenance；来源变化必须有显式转交和保管记录。
5. Detail 不存在非相邻语义重复章节；高潮受害者、地点和动作都由前文因果产生。
6. 每一前期具名道具和主线人物都明确回收、转义或标记为作者批准的开放项。
7. 必需 reviewer 全部 available；Fast 不静默越过 unavailable。
8. 允许模型文学告警被作者接受，但确定性身份、来源、时间和状态冲突不得进入 accepted。
9. 20 章完成后先做全书冷读决策，再进入 Cover/Export 发布验收。
10. 字数只要高于明显残缺门且内容完整即可，不为了靠近 5 万字隐藏重试或灌水。

## 12. 最终判断

这次 Run 最有价值的结论不是“DeepSeek 能不能写到 5 万字”，而是：**现有系统已经能稳定生产、持久化和写回长篇正文，但还不能稳定担任长篇小说的结构编辑与连续性编辑。**

问题的首要修复点也不是继续调大 Prompt 或反复重跑同一稿，而是把人物身份、证据来源、线索生命周期、章节戏剧任务和必需审稿可用性，从自然语言愿望升级为代码可比较的合同。完成这些 P0 后，再开一个全新 Run 做真实验收；本历史 Run 只保留为失败证据和回归样本。
