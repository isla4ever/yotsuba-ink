本文档用于定义 Yotsuba Ink 下一轮大规模产品、UI/UX 和工程重构的目标状态，并将 PlotPilot、React Bits、Aceternity UI、Uiverse、Anime.js 及同类小说创作工具中值得吸收的能力，转换为符合本仓库边界的实施路线。

1. Yotsuba Ink 的核心产品定位和用户价值是什么。
2. 当前阶段流水线与 PlotPilot 章节生产引擎之间应如何组合。
3. 每个阶段最终应呈现什么 Artifact、支持什么决策、写回什么系统。
4. UI 大升级应改什么，不应改什么。
5. 外部组件与动效方案适合进入哪些场景，哪些效果必须禁止或延期。
6. 前端、后端、状态、事件、记忆、质量和持久化应如何分期重构。
7. 每次迭代达到什么条件才可以进入下一阶段。

## 2. 产品决策摘要

### 2.1 最终定位

Yotsuba Ink 的目标不是成为聊天式写作助手，也不是成为纯无人值守小说生成器。

目标定位是：

> 面向长篇小说生产的多阶段 AI 创作工作台，通过结构化产物、人工决策、事实写回、质量阻断和可恢复执行，把立项、规划、写作、包装和交付组织成可审阅的生产链路。

产品必须同时解决五类问题：

- 从模糊创意到稳定写作蓝图。
- 从蓝图到连续章节正文。
- 长篇创作中的人物、世界、时间和伏笔一致性。
- AI 生成过程的成本、失败、恢复和质量控制。
- 用户对自动化程度和最终定稿权的选择。

### 2.2 与 PlotPilot 的关系

PlotPilot 更接近“长期运行的剧情引擎内核 + 章节工作台”，Yotsuba Ink 更接近“从立项到交付的阶段生产线”。

正确的学习方式不是整体复刻 PlotPilot，而是：

- 保留 Yotsuba Ink 的阶段链、三档模式和结构化 Artifact 合同。
- 在正文阶段吸收 PlotPilot 的章节生产管线、检查点、章后处理和运行可靠性设计。
- 将 PlotPilot 的知识图谱、伏笔、张力和快照能力转译为本项目的世界观、人物关系网、Wiki 和质量阀门。
- 将 PlotPilot 的运维监控降级为独立观测入口，不让它占据创作主界面。

### 2.3 产品主线决策

以下决策在本轮目标中视为确定项：

1. 阶段流水线继续作为产品主导航。
2. 三档模式继续作为用户控制权模型，而不是价格或 Token 标签。
3. Info 是 v1 默认硬人工闸门。
4. 精细定稿模式中，每个创作阶段都需要人工定稿。
5. 正文阶段切换为稿件优先的专业写作桌，不继续沿用普通阶段页面模板。
6. Wiki 升级为带来源、时序和状态的事实账本。
7. 质量阀门拆分为确定性检查、模型评审、修订指令和复检结果。
8. 真实 SSE 是运行状态的唯一事实源。
9. React Bits 只提供局部交互模式，不决定产品视觉风格。
10. 大规模 UI 升级必须与状态和文件边界重构同步进行。
11. UI 升级不是给现有页面统一加动画；先消除假控件、伪进度、草稿丢失和状态错配，再增加视觉反馈。
12. 每个阶段首屏只允许一个主 Artifact、一个阶段支撑栏和一个推进流程的主决策。
13. `motion/react` 是 React 状态过渡的唯一默认运行时；CSS 负责微交互，Anime.js 只允许进入隔离的 SVG、Canvas 或复杂时间线场景。
14. 空闲页面不得存在持续装饰动画；真实运行时也只保留当前状态点、必要 Spinner 和流式光标等少量状态动画。
15. 外部组件必须适配现有 Radix、Token、焦点和状态事实源，不整体复制默认视觉、DOM 结构或演示数据。
16. “免费展示”不等于“可直接商用复制”；每个外部实现进入代码前必须登记来源、版本、许可证、改造范围和保留声明要求。
17. 打开 Dialog、切换 Tab、切换章节、查看详情和播放过渡不得触发 Provider、`/resume`、SSE 重连、正式写回或重复计费。
18. 首次配置采用可退出、可恢复的五步引导；完成后设置入口改为单页摘要和局部编辑，不把四个技术 Tab 换皮成永久 Stepper。
19. 每个配置字段只有一个主编辑位置；默认模型、Provider Profile、阶段例外和系统自动保护不得在多个页面重复配置或伪装成同级开关。
20. 全应用表单按字段语义统一宽度、分组、错误和移动端重排；视觉统一不得改变 Artifact、隐藏字段、草稿保护和正式写回合同。

## 3. 研究对象与学习边界

### 3.1 PlotPilot 值得学习的能力

#### 章节生产管线

PlotPilot 将章节生产拆成稳定步骤，而不是把一次模型请求视为完整写作流程。Yotsuba Ink 应吸收以下阶段语义：

1. 章节定位。
2. 上下文装配。
3. 章节执行剧本准备。
4. 正文生成。
5. 策略和合同校验。
6. 章节稳定落盘。
7. 文风与连续性审计。
8. 章后摘要、事实和伏笔处理。
9. 张力和质量评分。
10. 当前章节结算并准备下一章。

#### 稳定提交边界

- 模型请求、流式 delta 和临时候选属于可重试步骤。
- 用户确认的 Artifact、已落盘章节和章后事实属于稳定提交。
- 恢复时从最后一个稳定提交点继续，不从整个阶段开头重跑。
- 重试不得重复写入同一事实、章节或使用量记录。

#### 运行可靠性

- 连续失败熔断。
- Provider 错误分类。
- 最大重试次数。
- 单阶段 Token 和费用预算。
- 检查点恢复。
- 运行心跳和停滞检测。
- 明确区分暂停、等待确认、失败和完成。

#### 章节工作台

- 左侧章节树提供位置感。
- 中间正文始终是最大工作面。
- 右侧只放当前章节真正相关的上下文。
- 运维、DAG 和指标进入独立视图或弹层。
- 分栏可折叠，但主稿件宽度不能被持续挤压。

### 3.2 PlotPilot 不应复制的部分

- 不复制其全量功能菜单和长期常驻观测面板。
- 不复制前端巨型组件和通用 `components/` 桶式目录。
- 不复制小字号、多面板、全部指标同时可见的控制台密度。
- 不复制无限自动推进和过度重试策略。
- 不复制把提示词调试、技术追踪直接暴露给普通创作者的做法。
- 不直接搬运受 Commons Clause 限制的实现代码。

### 3.3 同类产品可吸收的原则

#### NovelCrafter

- Codex 实体与场景、章节的明确关联。
- Scene/Beat 的矩阵式规划和筛选。
- 人物、地点、标签和剧情单元之间的可追踪连接。
- 只向模型注入当前任务真正需要的上下文。

#### Sudowrite

- 正文编辑器是第一视觉中心。
- AI 操作是局部、可召唤的写作工具，而不是常驻聊天框。
- 改写、扩写、压缩、描述等操作应作用于明确选区。
- 主题和专注模式服务于长时间写作舒适度。

#### Plottr

- 章节与剧情线的交叉视图。
- 按人物、地点、标签、伏笔和状态筛选场景。
- 拖拽排序必须对应真实结构写回，而不是纯视觉排序。

### 3.4 开源与社区调研补充

本轮通过 Agent Reach 检索 GitHub、Reddit、X、小红书与 Bilibili，并复核指定组件站点。社区内容只用于发现问题和交互方向，不作为许可证、质量或产品合同的唯一证据。

可吸收的共同信号：

- 长篇 AI 写作的主要痛点不是缺少一次性 Prompt，而是上下文漂移、角色 OOC、章节重复、结构失控和人工审阅成本。
- 高杠杆干预应尽量发生在 Brief、大纲、细纲和章节执行说明层；修改结构规格比正文生成后逐句返工更有效。
- 候选方案加人工反馈，比不断增加 Prompt 说明更容易让用户表达真实偏好，因此候选链路应是“少量候选、明确差异、手动选稿”，不是无限重生成。
- 用户希望 AI 承担生成、整理和检查等重劳动，但不愿交出题材方向、人物关系、节奏、事实成立与最终定稿权。
- 中文创作讨论中，“先搭骨架再扩写”“防止角色 OOC”“从混乱到可控的长文工作流”反复出现，验证了阶段 Artifact 和人物/事实账本的必要性。
- X 中较有价值的信号强调“先维护世界、人物、情节、声音等设计规格，再生成章节，并在最终稿阶段进行人工精修”，与本项目的 Brief -> Outline -> Detail -> Text 路径一致；高噪声工具推广不进入需求。
- Reddit 中 LumaLore、novl.studio、Arbento 等讨论反复强调正文旁的世界观访问、结构化 Manuscript Binder、场景元数据、快照、专门搜索和作者最终控制权；营销式 KDP“一键成书”内容只作为反例。
- 开源写作工具 `novelWriter` 的项目树、场景/章节组织和专注写作思路值得参考；不得将桌面软件的信息密度和交互习惯原样搬到网页端。
- 引导式全流程能减少跨工具复制与上下文断裂，但“可导出”绝不等于“无需人工编辑即可交付”。

由此形成三条产品判断：

1. 先让每次人工干预有明确对象、影响范围和写回结果，再讨论页面是否更“丰富”。
2. 可视化只表达用户难以从文本快速判断的关系、节奏、覆盖、冲突和版本差异。
3. 动效只解释状态变化、空间关系和操作结果，不承担制造高级感的任务。

## 4. 当前产品主流程

### 4.1 阶段链

```text
配置准备
  -> 小说信息推荐
  -> 全书梗概
  -> 分卷大纲
  -> 章节细纲
  -> 正文生成
  -> AI 封面
  -> 导出交付
```

### 4.2 各阶段核心任务

| 阶段 | 核心 Artifact | 用户决策 | 主要写回 | 下一阶段依赖 |
| --- | --- | --- | --- | --- |
| 配置 | Workflow 配置与创作 Brief | 是否具备启动条件 | 工作流、知识库、Provider | Info 输入 |
| Info | Story Brief | 项目方向是否成立 | 世界观、人物关系 | Summary |
| Summary | 全书故事主干 | 故事是否值得继续 | Memory、Story Bible、连续性摘要、人物图谱 | Outline |
| Outline | 分卷和节拍结构 | 中观节奏是否成立 | 人物、世界、伏笔计划 | Detail |
| Detail | 章节施工图 | 每章是否可执行 | Wiki 候选、关系变化、上下文 | Text |
| Text | 章节正文 | 内容是否可定稿 | Wiki、人物状态、章节摘要 | 下一章/Cover |
| Cover | 封面资产 | 选择最终方案 | 选中资产、封面元数据 | Export |
| Export | 交付包 | 格式与内容是否可交付 | Manifest、导出记录 | 完成 |

## 5. 三档模式目标合同

### 5.1 极速生产

目标用户：希望低干预快速得到完整样稿的用户。

目标体验：

- 配置态和运行态都留在单页 Cockpit。
- 启动后自动推进全链路。
- 不提供运行中暂停和阶段跳转。
- 左侧显示阶段链，中间显示当前产物流，右侧显示必要的关系和设定摘要。
- 默认不展示技术日志、原始事件和完整质量报告。
- 失败时明确停止并显示原因，不静默自动死循环。
- 结束后提供查看产物、导出和重新开始。

### 5.2 平衡创作

目标用户：希望先定方向，再让系统自动生产的主流用户。

目标体验：

- 配置态使用标准 Pipeline Canvas。
- Info 阶段必须人工确认。
- Info 确认后进入自动 Cockpit。
- 后续阶段自动执行，不强制打开详情页。
- 后续产物只能从 Cockpit 打开只读详情 Dialog/Sheet；当前合同不新增 Summary/Outline/Detail/Text 独立路由。
- 版本对比是可选能力，只在用户主动触发后运行。
- 不自动生成多个候选消耗额外 Token。

### 5.3 精细定稿

目标用户：希望逐阶段审稿并掌握最终决策权的专业用户。

目标体验：

- 每个阶段都有独立路由和专业 Artifact 工作台。
- 生成完成后进入等待定稿态。
- 用户可以编辑、局部重写、换一稿、选择候选并确认定稿。
- 只有确认定稿后，Header 才允许继续。
- 文本阶段候选最多三栏，用户手动选择。
- 质量系统可以阻断，但不能替用户自动定稿。

### 5.4 模式间不可混淆的状态

| 状态 | 极速 | 平衡 | 精细 |
| --- | --- | --- | --- |
| Info 人工确认 | 否 | 是 | 是 |
| 后续阶段人工确认 | 否 | 否 | 是 |
| 自动进入下一阶段 | 是 | Info 后是 | 否 |
| 模型自动择优 | 否 | 用户主动触发时可用 | 否 |
| 手动换稿 | 结束后有限支持 | Info 支持 | 各创作阶段支持 |
| 运行中暂停 | 否 | 可恢复暂停 | 阶段间和正文可暂停 |

## 6. 目标信息架构

### 6.1 全局壳层

全局壳层只承担以下职责：

- 品牌和当前项目。
- 当前模式。
- 当前阶段和总进度。
- 运行状态。
- 唯一主操作。
- 历史、设置、知识库等全局入口。

Header 不应同时展示完整 Token 仪表、质量详情、模型参数和所有阶段操作。

### 6.2 页面层级

```text
App Shell
  ├─ Planning Workbench
  │   ├─ Pipeline Canvas
  │   ├─ Knowledge Status
  │   └─ Stage Inspector
  ├─ Production Cockpit
  │   ├─ Stage Rail
  │   ├─ Artifact Stream
  │   └─ Runtime Summary
  └─ Stage Workbench
      ├─ Artifact Surface
      ├─ Stage Insights
      ├─ Stage Decision Bar
      └─ Global Dialogs
```

### 6.3 页面优先级

从高到低固定为：

1. 当前阶段 Artifact。
2. 当前用户决策。
3. 与当前决策直接相关的上下文。
4. 质量和写回状态。
5. 运行观测。
6. 装饰和动效。

任何新模块如果不能明确支持前四项之一，应默认不进入主界面。

## 7. 全局 UI/UX 目标

### 7.1 视觉方向

目标是专业、安静、长时间可用的创作工作台，而不是科幻展示页。

视觉基准：

- 中性墨色或冷灰作为应用壳层。
- 正文、梗概和蓝图使用高可读纸张面或编辑面。
- 模式色只用于选中、进度、主按钮和局部强调。
- 成功、警告、阻断使用独立语义色，不与模式色混用。
- 普通面板圆角控制在 4-8px。
- 减少发光、网格、重渐变和多层描边。
- 禁止卡片嵌套卡片。
- 主工作面不使用营销式大标题。

### 7.2 模式色

| 模式 | 主色语义 | 使用位置 | 禁止用法 |
| --- | --- | --- | --- |
| 极速 | 清晰蓝 | 运行进度、当前节点、启动 | 全屏蓝色发光背景 |
| 平衡 | 青绿 | 确认后自动接续、稳定状态 | 把所有成功状态都染绿 |
| 精细 | 克制紫 | 编辑、定稿、候选选中 | 大面积紫色渐变和霓虹 |

### 7.3 排版与密度

- 工作台正文基础字号不低于 14px。
- 表格和紧凑元数据可使用 12-13px，但必须保持足够行高。
- 面板标题控制在 14-18px。
- 页面级标题不超过 24px。
- 不使用随视口宽度缩放的字体。
- 中文文本不使用负字距。
- 主稿件行宽控制在适合长文阅读的范围。
- 表格固定关键列宽，长文本采用两行摘要或详情弹层。

### 7.4 交互原则

- 图标按钮使用 Lucide 图标并提供 Tooltip。
- 二元设置使用 Switch 或 Checkbox。
- 模式选择使用 Segmented Control。
- 数值使用 Input、Stepper 或 Slider。
- 阶段详情和写回使用全局居中 Dialog。
- 观察面板详情使用侧边 Sheet 或全局 Dialog，不嵌在局部卡片中。
- 破坏性操作必须二次确认。
- 自动保存必须显示短暂、非阻塞状态。
- 错误状态必须提供重试、返回或查看原因。

### 7.5 响应式策略

产品以桌面创作场景为主，但不能依赖单一宽度。

| 宽度 | 目标布局 |
| --- | --- |
| 1728 及以上 | 主 Artifact + 完整支撑栏 |
| 1280-1727 | 主 Artifact + 紧凑支撑栏 |
| 1024-1279 | 主 Artifact + 可折叠侧栏 |
| 768-1023 | 单主区 + 抽屉式导航和洞察 |
| 768 以下 | 查看、确认和轻编辑；固定格式表格在自身容器横滑，洞察进入全屏 Sheet |

### 7.6 首屏信息合同

任一阶段首屏在 3 秒内必须回答三个问题：

1. 当前正在审阅或编辑的产物是什么。
2. 现在需要用户做出的决定是什么。
3. 哪个操作会保存并推进链路。

所有创作阶段统一使用以下结构，但内容与布局必须按 Artifact 专门设计：

| 目标组件 | 固定职责 | 不允许承担的职责 |
| --- | --- | --- |
| `StageContextBar` | 产物名称、草稿/已确认状态、真实问题数 | 重复全局阶段进度、模式介绍、技术阈值 |
| `StageReadiness` | “可定稿”或最多 3 个具体缺失项，支持定位 | 只显示抽象分数、固定通过率或伪完整度 |
| `StageInspectorRail` | 与当前决策直接相关的一个主观察区和一个切换区 | 纵向堆满人物、世界、Wiki、质量和日志 |
| `StageFinalizeTray` | 一个次操作与一个主操作，状态和尺寸稳定 | 同时放置多个同权重主按钮或推动正文布局 |
| `WritebackPreview` | 说明当前稿定稿后将写到哪里 | 在确认前声称已经同步或成为正式事实 |
| `CandidateCompare` | 方向、最多三稿、差异、选择和返回单稿 | 无限候选、自动替用户选稿、显示原始 JSON |
| `FocusedDialog` | 编辑一个业务对象，保存/取消语义稳定 | 一个弹窗混合人物、Wiki、伏笔等不同写回目标 |

稳定桌面壳层采用“阶段导航 + 主 Artifact + 可收起支撑栏 + 决策栏”。进入候选对比时，主 Artifact 临时切换为对比面，常驻支撑栏隐藏，历史、质量和运行信息改从全局 Dialog 或 Sheet 打开。

### 7.7 内容进入主界面的价值门槛

内容只有满足以下至少一项才可以常驻：

- 直接影响当前人工决策。
- 能定位阻断、缺失或冲突。
- 能解释当前 Artifact 与下一阶段的依赖。
- 是当前正在编辑的主要内容。

以下内容默认折叠、进入详情或彻底删除：

- Provider 名、内部事件名、Seed、原始 JSON、Prompt 中间步骤和技术教程文案。
- 固定候选数、固定完成率、节点数冒充质量数、章节总数/章节总数等伪指标。
- 重复页头、英文 eyebrow、重复模式名和重复阶段说明。
- 与当前 Artifact 无关的人物、世界、Wiki、质量和运行日志全家桶。
- 解释 UI 为什么这样设计的自我说明，例如“不要堆字段”“施工合同”“Header 会变绿”。
- 为填空白而增加的统计卡、装饰轨道、光球、背景网格和无操作意义的状态徽章。

### 7.8 交互真实性 P0 门槛

下列问题必须在全局美化和动效铺开前解决，否则不允许进入 Phase 8 的视觉实施：

| 问题 | 当前风险 | 目标处理 |
| --- | --- | --- |
| Detail 章节切换会重置未保存蓝图和写回草稿 | 用户输入永久丢失 | 切换前保存、放弃或留在当前章三选一；三类写回拆成独立编辑器 |
| Export 生成中仍可“全选/清空” | UI 选择与已生成文件不一致 | 生成期间冻结选择快照；完成结果明确绑定该快照 |
| Planning 运行层存在未写回的下拉框 | 可编辑外观与真实行为不一致 | 接入真实配置写回，或改为只读状态，不保留假控件 |
| 知识库删除和 Header 重置无确认 | 破坏性操作不可恢复 | 二次确认；可撤销的删除优先提供撤销窗口 |
| 手写 Dialog 背景点击或 Esc 直接丢草稿 | 用户无法安全探索其他内容 | 统一脏态保护、关闭确认、焦点恢复和 Busy 锁定 |
| 候选显示原始 JSON 兜底 | 暴露实现细节且不可读 | 每阶段提供专用摘要适配器；解析失败进入明确错误态 |
| Cover 用 CSS 构图冒充生成图 | 用户无法判断真实交付物 | 只显示真实候选；占位必须明确标注“尚未生成” |
| 全局隐藏滚动条 | 长文、表格和弹层缺少滚动可发现性 | 恢复系统滚动条或提供稳定边缘线索，不隐藏关键滚动容器 |
| 所有 Disabled 使用等待光标 | 禁用、无权限和处理中语义混淆 | `not-allowed`、普通禁用和 Busy Spinner 分离 |

### 7.9 可访问性与输入方式

- 所有流程必须可以仅用键盘完成，Canvas 同时提供可聚焦阶段列表作为等价入口。
- `Tab`、`Arrow`、`Home/End` 和 `Escape` 行为遵循 ARIA 组件模式；视觉 Tab 必须具有 `tablist/tab/tabpanel` 语义。
- 焦点环即时出现，不等待动画；Dialog 和 Sheet 关闭后焦点返回触发器。
- Canvas 图谱必须提供同步的节点列表或关系 Ledger，不能只支持鼠标命中。
- Hover 只提供增强信息，不能承载唯一操作或唯一状态。
- 触控目标桌面不低于 32px，移动端不低于 44px；正文元数据不得低于 11-12px，移动端正文相关文本不得低于 12px。
- 错误和阻断使用 `role="alert"`，非阻塞保存与同步使用 `role="status"`；不能只靠颜色表达。
- `prefers-reduced-motion` 下功能、空间关系和状态语义保持完整，不依赖位移、模糊、缩放或自动平滑滚动。

### 7.10 响应式行为细则

- 390px 下页面本身不得横向溢出；章节表、Beat Board 等固定格式组件允许在自身容器内横向滚动，并保留 Sticky 首列。
- 复杂表格不强行改成厚卡片列表；移动端优先使用整体横滑、列显隐和详情全屏化。
- 三栏候选在窄屏改为单候选分页或分段切换，始终保留选中状态、候选编号和明确比较入口。
- 右侧 Inspector 在 1024px 以下改为全屏 Sheet 或底部面板，不串联到长页面末尾。
- `StageFinalizeTray` 在移动端固定于安全区底部，并为正文预留同等高度，避免遮挡最后内容。
- Dialog 在移动端转为全屏或近全屏，只保留一个内部滚动区；页脚操作固定但不得遮挡输入。
- 封面使用稳定 2:3 画框；候选、加载文案和选中标记不得改变画框尺寸。
- 320/390/768/1024/1180/1280/1440/1728 均作为布局断点验收，而不是只测桌面和手机两个极端。

### 7.11 全局壳层组件细化

| 组件 | 常驻内容 | Hover/Active/Focus/切换合同 |
| --- | --- | --- |
| `AppHeader` | 品牌/项目、当前阶段事实、全局入口 | Header 不随阶段重播；中屏两行、移动端稳定三行；任何状态变化不改变整体高度 |
| `StageProgressNavigator` | 已完成、当前、等待、失败阶段 | Hover 显示可读标签；Active 使用稳定指示器；未授权阶段不可点击；键盘可遍历 |
| 模式 Segmented Control | 极速、平衡、精细 | Selected 指示器平移；运行开始后按合同锁定并解释原因；模式色不扩散到全页 |
| `CreationStatusCluster` | Run 状态、保存/恢复、必要预算预警 | 只消费真实状态；文字宽度预留；错误进入持久详情而非闪烁徽章 |
| `CreationActionDock` | 当前唯一全局主操作及必要次操作 | 主按钮稳定宽度；Busy 防重；自动模式不展示不可用的阶段定稿栏 |
| 历史入口 | 未完成/历史提示与抽屉触发 | 图标 + 可读 Label/Tooltip；打开抽屉不暂停、不恢复、不请求 Provider |
| 设置/知识库入口 | 全局配置与资料状态 | Icon Button 固定尺寸；错误点只在真实阻断时出现；Focus 即时 |
| Route Fallback | 无权限、缺 Run、未知阶段、加载失败 | 说明原因和返回路径；不自动调用 `/resume` 或静默跳到错误阶段 |
| Global Toast Layer | 保存、同步、错误、进度 | 统一层级、图标和 Live Region；错误持久，成功短暂，不能被 Dialog 裁切 |

全局壳层只允许静态纸纹、细分隔线和状态色内描边等低对比静态效果。Logo、Header 背景、模式按钮和阶段节点不使用 Aurora、星空、流光、持续阴影呼吸或跟随鼠标光斑。

## 8. 分阶段目标工作台

### 8.0 人工干预总合同

人工干预不是每个阶段都塞一组“确认/换稿”按钮，而是由模式、Artifact 就绪度和真实阻断共同决定。

| 模式 | 默认干预策略 | 候选策略 | 阻断策略 |
| --- | --- | --- | --- |
| 极速生产 | 不设置常规人工闸门，运行观察按需打开 | 默认不生成多候选 | 仅真实配置、Provider、合同、预算或质量硬错误停止 |
| 平衡创作 | Info 强制定稿；后续阶段保持自动接续 | 用户主动请求时生成少量候选 | 非阻断建议不打断链路，硬错误进入恢复 |
| 精细定稿 | Info、Summary、Outline、Detail、Text、Cover 逐阶段定稿 | 允许换稿、对比和人工选稿 | 缺少必需字段、未决写回和质量阻断时禁止定稿 |

所有阶段共享同一状态词汇；具体节点按模式跳过，Fast/Balanced 自动阶段不会为了视觉完整而伪造“等待定稿”：

```text
未开始 -> 生成中 -> 可审阅 -> 编辑中 -> 校验中
       -> 等待定稿 -> 已确认 -> 自动/手动进入下一阶段
                    \-> 修订/候选 -> 再校验
任意运行态 -> 暂停/失败 -> 明确恢复 -> 回到最后稳定状态
```

交互边界：

- 打开、关闭、切 Tab、切详情、选择行、预览候选均为本地交互，不调用 Provider。
- 只有“生成”“换一稿”“生成修订候选”等明确命令可以新增 Provider 调用。
- 保存草稿和正式定稿分离；保存不等于确认，确认不允许隐式覆盖用户尚未保存的修改。
- Deep 换稿与 Info 候选路径为：填写方向 -> 生成最多三稿 -> 比较 -> 明确选稿 -> 返回单稿 -> 单独定稿。
- Deep 的 `DraftCandidateCompare` 对应“换稿并手动选稿”；Balanced 的 `VariantCompare` 只从 Cockpit 主动触发，允许模型生成版本并择优。两者不得共享用户文案、事件名和批准语义。
- Balanced 后续产物不出现独立阶段路由过渡，详情只在 Cockpit 的只读 Dialog/Sheet 内切换；如果未来开放路由，必须先修改运行状态与路由合同。
- `WritebackPreview` 必须标注“当前稿预览，定稿后写回”；正式写回只由后端确认结果更新 UI。
- 阻断提示最多展示 3 个最重要问题，其余进入详情；每项必须有定位或修复动作。
- `StageFinalizeTray` 只在当前模式和阶段确有人工闸门时渲染；Fast 和 Balanced 自动阶段不显示一条 Disabled 的定稿栏。

以下 8.2-8.7 独立阶段工作台主要对应 Deep；Info 同时服务 Balanced 的硬闸门。Fast/Balanced 后续阶段的同一 Artifact 通过 8.9 Cockpit 的只读详情消费，不因此新增独立路由。

### 8.1 配置阶段

#### Artifact

- 小说基础 Brief。
- 知识库状态。
- Provider 和模型选择。
- 三档模式。
- 阶段参数。
- 输出偏好。

#### 用户决策

- 当前项目是否具备启动条件。
- 选择哪种自动化程度。
- 哪些资料和约束进入生成链路。

#### 目标布局

- 首次进入：`GuidedSetupWorkbench` 占据主区，按“故事起点 -> 参考方式 -> 创作方式 -> AI 服务 -> 开始前确认”顺序完成必要准备。
- 首次流程：左侧/顶部是紧凑步骤导航，中间只有当前步骤表单，底部固定“保存后退出 / 上一步 / 继续或开始创作”。
- 完成准备后：主区切换为横向 Pipeline Canvas，下方为知识库状态带，右侧只显示当前阶段必要字段和默认收起的“阶段例外”。
- Header：只显示配置摘要或最早缺项、模式、设置和开始，不常驻五步 Stepper，也不重复七阶段进度。
- 后续设置：单页 Settings Overview + 局部编辑，不要求用户重走首次流程。

#### 目标改进

- 首次用户不再为了完成启动准备在 Canvas、Inspector、Knowledge 和 Settings 之间来回跳转。
- 减少完成准备后 Canvas 的大面积无信息空白。
- 阶段节点文字和状态必须在 1280 宽度可读。
- Inspector 首屏只显示当前决策需要的字段。
- Provider Profile 和默认模型只在 AI 服务区域配置；阶段 Provider/模型、Temperature、Max Tokens 只进入对应阶段的“阶段例外”。
- 模式选择显示完整名称和一句差异，不只显示单字图标。
- 表单按 Short/Medium/Full 宽度语义布局；同一行等宽等高，720px 以下单列，错误就近显示并可定位。

#### 组件与交互细化

| 组件 | 常驻信息 | 状态与动效 | 关键约束 |
| --- | --- | --- | --- |
| `GuidedSetupWorkbench` | 当前步骤、真实完成度、最多 3 个阻塞 | 步骤内容短淡入；完成 Check 只播放一次 | 步骤从 Workflow/Knowledge/Readiness 派生，不复制完成真值，不表达七阶段运行进度 |
| 首次表单 Section | 当前任务所需字段、输入示例、就近错误 | Focus/Error/保存状态不改变几何 | 只有语义并列字段可双列；一屏一个主动作；可选内容可明确跳过 |
| Pipeline 阶段节点 | 产物名、就绪/缺失、当前选择 | Hover 仅增强边框；Active 使用稳定内描边；Focus 即时；完成状态一次 220ms 高亮 | 单击选择，双击不能成为唯一打开详情方式；节点不因状态改变尺寸 |
| 模式 Segmented Control | 极速/平衡/精细完整名称 | 指示器 180ms 平移；内容区不重挂载 | 切模式先展示影响摘要，运行开始后按合同锁定 |
| `StageInspector` | 当前阶段的必填项、输出偏好、模型高级项 | 分组展开 160ms；错误保存后定位并聚焦 | Wiki/质量能力若未真实可写，只能只读展示，不得使用假下拉框 |
| 知识库状态带 | 文档、片段、索引、失败项、来源 | 上传使用真实进度；成功一次高亮；错误保持可复查 | 上传/删除 Busy 时阻止重复提交；删除需确认或撤销 |
| `StageReadiness` | 总体可启动或最多 3 个缺失项 | 校验结果淡入，不播放 CountUp | 点击缺失项选择对应阶段并定位字段 |
| “启动创作” | 唯一主操作 | 120ms Hover、80ms Press、Busy 宽度稳定 | 100ms 内出现反馈；重复点击不创建第二个 Run |

高级弹层按职责拆分为知识库管理、Provider/模型管理、Prompt 高级配置和阶段高级参数。每个弹层只保留一个滚动容器，脏态关闭需确认，保存成功后返回原触发位置。

极速/平衡 Cockpit 只在 Run 已创建后展示 Wiki、质量和运行详情。预运行时相关入口显示“启动后可用”的禁用状态，不得出现可点击但无反应的按钮。运行日志、节点、背景和游标不得同时循环；只允许当前运行节点和必要进度保持动态。

移动端首次流程使用 `x/5 + 当前步骤`、单列表单和 Safe Area 底部动作；软键盘不能遮挡错误和继续按钮。首次完成后使用可横滑阶段总览和全屏阶段配置 Sheet，不把完整 Inspector 堆在 Canvas 下方。Canvas 必须同时提供键盘阶段列表，保证不依赖缩放、拖动和双击。

#### 验收

- 新用户 30 秒内能理解三档模式差异。
- 新用户能沿一个连续流程完成必要配置；中途退出后恢复到上次位置，前序配置失效时定位最早阻塞。
- 必填项缺失时开始按钮明确说明原因。
- 再次进入设置看到摘要和局部修改入口，不重复展示四个交叉 Tab 或七阶段完整 Provider 表单。
- 配置态不出现人物关系、世界观运行面板、Wiki 或质量阀门。

### 8.2 小说信息推荐

#### Artifact

- `selected_title`
- `title_candidates[]`
- `synopsis`
- `worldbuilding_detail`
- `characters[]`
- `relationships[]`
- `tags[]`
- `downstream_constraints[]`，可折叠但写回必须保留。
- `risk_notes[]`，仅在真实风险或详情中展示。
- `characters[].growth_direction`，人物 Ledger 和编辑器必须保留。

#### 用户决策

- 是否接受项目方向。
- 最终书名是什么。
- 世界观和人物是否足以支撑后续结构。

#### 写回

- 初始化世界观锚点。
- 初始化人物实体和关系边。
- 将确认稿写为 Story Brief 基线版本。

#### 目标布局

- 顶部：书名候选和轻量定位标签。
- 左侧主区：简介、世界观、人物记录编辑。
- 右侧：世界观摘要和人物关系网。
- 底部：换一稿、确认推荐。

#### 人工干预与组件细化

用户在本阶段只做一项主决策：书名、简介、世界观硬约束、主要人物和关系能否成为整条创作链的基线。

| 区域/组件 | 展示与操作 | 细节合同 |
| --- | --- | --- |
| 书名选择器 | 紧凑单选列表 + 自定义书名 | Active 必须有 `aria-pressed` 或 radio 语义；Hover 不改变行高；键盘可上下选择 |
| 简介稿纸 | 单一可读/可编辑表面 | 阅读态与编辑态互斥，不同时重复正文；保存显示真实草稿状态 |
| 世界观摘要 | 时间、空间、规则、社会四类定义摘要 | 只展示已填写内容和缺失项；完整编辑进入独立 Dialog |
| 人物 Ledger | 姓名、定位、目标、冲突、成长方向 | 一行一人；关系和档案编辑进入人物专用 Dialog，不嵌套卡片 |
| 人物关系图 | 当前确认草稿中的真实节点和边 | 图谱旁提供等价列表；节点选择打开全局详情，不在图内堆文字 |
| `StageFinalizeTray` | 次“换一稿”、主“确认推荐” | Deep/Balanced 可用；成功只由审批响应触发，按钮不因文案变化跳动 |

换稿流程使用方向 Dialog 和 `CandidateCompare`。候选最多三栏，显示书名、简介差异、世界观方向和人物变化摘要；不得显示 Seed、Prompt、原始 JSON 或大段“推荐理由”。选稿只替换当前草稿，仍需单独确认。

生成阶段允许使用全局遮罩，但必须由真实 SSE 状态驱动。没有细粒度事件时只显示中性的“正在生成项目信息”，不能固定播放 5 秒、伪造步骤完成或提前显示成功。完成后只对新增产物做一次 180ms 淡入。

世界观和人物编辑器有未保存修改时，点击背景、Escape、切换对象或关闭均触发脏态保护。保存后 `WritebackPreview` 只说明“确认后初始化人物/世界基线”，不得提前显示“已同步”。

移动端按书名 -> 简介 -> 世界观 -> 人物顺序单列，图谱和完整世界观进入顶部可切换全屏 Sheet；确认栏固定安全区底部。推荐理由墙、知识库依据墙、装饰 Orbit、Hero Card 和重复继承说明不进入首屏。

#### 状态

- 检索中。
- 生成中。
- 可编辑。
- 同步中。
- 等待确认。
- 已确认只读预览。
- 生成失败。

#### 验收

- 不显示原始 JSON、Seed、推荐理由大板块或内部风险日志。
- 用户修改世界观和人物后，对应系统显示同步反馈。
- 确认前不能继续，确认后不再允许无提示覆盖基线。

### 8.3 全书梗概

#### Artifact

- `one_liner`
- `full_synopsis`
- `act_structure[]`
- `core_conflict`
- `character_arcs[]`
- `key_turns[]`
- `ending_resolution`
- `consistency_checks[]`

#### 用户决策

- 故事主干、人物选择和结局是否成立。
- 是否需要局部重写或换稿。

#### 写回

- Memory 中的梗概稳定版本。
- Story Bible 与连续性摘要。
- 人物弧和关系压力写入人物图谱。
- 质量问题与修订指令。

#### 目标布局

- `one_liner` 作为顶部方向条。
- 左侧全高为 `full_synopsis` 稿纸。
- 右上为幕结构和关键转折轨。
- 右下为人物关系深化 Ledger。
- 质量问题通过紧凑入口和阻断提示呈现。

#### 人工干预与组件细化

本阶段的主问题是“故事因果链、人物变化、关键转折和结局承诺是否成立”，不是逐字段填完一张表。

| 组件 | 内容密度 | 交互与过渡 |
| --- | --- | --- |
| 核心方向条 | 一句话主线 + 当前稿状态 | 固定高度；编辑后只做边框状态变化，不使用滚动文字 |
| 梗概稿纸 | 完整 `full_synopsis`，占主区最大面积 | 阅读/编辑两态切换；正文块按句段 140-180ms 淡入，不逐字打字、不模糊 |
| 幕结构轨 | 3-5 个真实幕段、目标和结局作用 | 固定语义轨道；当前项用边框/底色，Hover 不抬升 |
| 关键转折阶梯 | 顺序、触发、结果 | 纵向或横向序列；点击打开单转折编辑器 |
| 人物弧摘要 | 人物起点、压力、变化、终点 | 主区只保留变化摘要；完整关系进入右侧图谱或全局详情 |
| Inspector 切换区 | 人物图谱常驻，世界观/质量二选一 | Tab 指示器 180ms；内容 Exit 100-120ms、Enter 160-180ms；不重置滚动或选择 |

按需弹层只包括完整梗概编辑、单幕/单转折编辑、人物弧深化、冲突与结局承诺、换稿方向和候选比较。每个弹层编辑一个对象，禁止将所有结构字段重新堆成通用大表单。

流式完成后进入可审阅态；用户编辑后进入脏态；显式校验完成后才允许 Deep 定稿。定稿成功后人物弧与 Memory 幂等写回。Balanced 的非阻断版本对比只能从自动 Cockpit 主动触发，Summary 独立页面不为 Balanced 提供入口或强制闸门。

移动端优先稿纸；幕结构和关键转折使用语义 Tab；人物、世界观和质量进入全屏 Sheet。删除重复关系小地图、重复正文 textarea、英文页头和抽象质量分数。

#### 验收

- 完整梗概始终是视觉中心。
- 关键转折按顺序可扫描，不使用复杂装饰轨道。
- 流式生成完成后正文不消失、不重复显示。

### 8.4 分卷大纲

#### Artifact

每卷包含：

- `title`
- `chapter_range`
- `volume_goal`
- `rhythm`
- `opening`
- `development`
- `midpoint`
- `climax`
- `resolution`
- `character_progression[]`
- `world_reveal[]`
- `foreshadow_plan[]`

#### 用户决策

- 卷数和章节范围是否合理。
- 节奏是否递进。
- 每卷是否承担明确结构职责。

#### 目标布局

- 主区使用紧凑卷列表和横向 Beat Board。
- 当前卷显示目标、章节范围和节奏条。
- 卷详情使用全局居中编辑器。
- 人物承接、世界观承接和伏笔计划使用三个独立写回 Dialog。

#### 人工干预与组件细化

用户需要判断每卷目标、章节范围、节拍推进、人物承接、世界揭示和伏笔计划能否支撑整本书的中观节奏。

| 组件 | 展示 | 状态与操作 |
| --- | --- | --- |
| 分卷 Rail | 卷名、章节范围、真实就绪度 | Active 使用稳定左边线；切卷保存当前滚动；不靠 Hover 暴露唯一动作 |
| 当前卷命令条 | 卷目标、范围、真实缺失数 | 固定高度；编辑进入卷设置 Dialog，不堆小卡 |
| 节奏条 | 按章节或 Beat 的离散强度/折线 | 数据变化时一次 180-240ms 补间；无数据时显示缺失，不生成装饰波形 |
| 五列 Beat Board | 开篇、发展、中点、高潮、收束 | 列宽和卡槽稳定；当前生成项高亮；不为每段加厚重独立卡片 |
| 三类承接入口 | 人物、世界、伏笔的摘要与缺失 | 三个独立入口和 Dialog；各自保存、校验、写回目标互不混用 |

单卷流式生成时只高亮当前卷/Beat；完成项保持静止。调整章节范围后必须重新校验重叠、空洞和 Detail 下游约束，不能只改变标签。

卷切换、Beat 切换、Dialog 打开本身不触发 Provider。只有明确的“单卷换稿”或“重新生成节拍”允许请求模型，并在调用前展示影响范围。

移动端将卷 Rail 改为分段选择器，Beat Board 作为一个固定格式整体横向滚动，边缘使用静态渐隐或可滚动提示；人物、世界和伏笔三个承接入口纵向排列。删除“不要堆字段”等设计说明，只保留卷数、范围、就绪度和真实问题。

#### 验收

- 支持多卷，不为单卷样例写死布局。
- Beat 不变成厚重卡片堆叠。
- 三类写回不能混在一个通用表单。
- 调整卷章节范围后，后续细纲约束同步更新。

### 8.5 章节细纲

#### Artifact

每章包含：

- `chapter`
- `pov`
- `scene`
- `goal`
- `entry_state`
- `conflict`
- `stakes`
- `fact_reveals[]`
- `foreshadow[]`
- `character_shift`
- `hook`
- `continuity_notes`
- `wiki_candidates[]`

#### 用户决策

- 每章是否具备可执行的场景目标和冲突。
- 章节之间是否连续。
- 事实、伏笔和人物变化是否分布合理。

#### 目标布局

- 主区为高密度章节施工表。
- 一行对应一章。
- 表格列显示章节、POV/场景、目标/冲突、事实/Wiki、伏笔/Hook 和状态。
- 点击一章打开章节蓝图稿纸。
- 右侧紧凑 Ledger 跟随选中章节。

#### 专用写回

- 人物变化 Dialog。
- 世界观/Wiki 事实 Dialog。
- 伏笔账本 Dialog。

#### 人工干预与组件细化

本阶段不是阅读“大纲说明”，而是判断每章是否已经成为正文可直接执行的施工图，并能正确承接人物、事实、伏笔和连续性。

| 组件 | 主信息 | 交互合同 |
| --- | --- | --- |
| 章节施工表 | 章号、POV/场景、目标/冲突、事实/Wiki、伏笔/Hook、状态 | 一行一章；Sticky 章节列；Hover 只改背景/边框；生成行一次高亮，不抬升行 |
| 章节蓝图 Dialog | 当前章完整施工字段 | 切章前检查脏态；保存后仍停留当前章；Busy 时禁止切章和关闭 |
| 人物变化编辑器 | 入场状态、变化、离场状态、关系影响 | 独立 Dialog、独立校验、独立写回预览 |
| 事实/Wiki 编辑器 | 新事实、引用事实、时间、来源、冲突 | 动态条目使用稳定 ID，不能用数组索引维持输入身份 |
| 伏笔账本编辑器 | 投放、推进、回收、延后和目标章 | 独立状态机；未闭合项可定位，不与 Wiki Tab 混合 |
| 选中章摘要 | 事实/伏笔数量、缺失和短 delta | 只显示一条短预览，完整内容进入对应编辑器 |

`DetailWritebackHubDialog` 目标形态必须拆成三个独立业务编辑器。共享的只允许是 `FocusedDialog` 壳层、脏态保护、页脚和字段原语，不能继续用同一个 Tab Hub 混合三种正式写回语义。

章节切换、表格筛选和展开蓝图只改变本地选择，不请求 Provider。逐章生成只高亮当前行；定稿前执行章节范围、引用、事实唯一性和伏笔目标校验；确认后按人物、事实/Wiki、伏笔三个目标幂等写回。

“章节覆盖”必须来自真实必填字段和引用校验，不得固定显示总数/总数。删除施工合同说明和大段过程 delta。移动端保留表格整体横向滚动与 Sticky 章节列，蓝图和三个写回编辑器分别转为全屏 Dialog。

#### 验收

- 事实、Wiki、伏笔和人物变化不被合并为“章节说明”。
- 当前生成行可以高亮和显示短 delta，完成行保持稳定。
- 确认后形成正文阶段可直接消费的 Context Packet。

### 8.6 正文生成

#### Artifact

- 当前章节 Context Packet。
- 流式正文 delta。
- 章节完成稿。
- 修订和候选版本。
- 质量报告。
- Wiki 写回提案。
- 章节摘要。

#### 用户决策

- 当前章节是否可继续、修订或定稿。
- 哪些事实和人物变化成为正式 Canon。
- 是否接受质量修订建议。

#### 目标布局

```text
章节树             正文编辑器                  当前章节上下文
卷/章导航           主稿件                      质量阀门
状态和字数           选区 AI 操作                Wiki 写回
搜索/筛选            修订历史                    人物/世界摘要
```

#### 目标交互

- 正文是最大工作面。
- 流式文本按句子或短行平滑写入。
- 选中文本后出现改写、扩写、压缩、换风格等局部操作。
- 章节树显示 planned/running/review/confirmed/failed。
- 右侧上下文可折叠为图标轨。
- 质量阻断显示明确问题和修复动作。
- Wiki 写回先作为提案，经规则或用户确认后成为 Canon。

#### 人工干预与组件细化

正文阶段每个时刻只突出一个当前任务：审阅正文、修复质量问题、同步摘要、处理写回提案或最终定稿。章节级修订、摘要复检和提案决策属于章节闭环；“确认定稿”只在整个 Text 阶段满足合同后出现，不为每章制造一个阶段确认闸门。主按钮随真实状态变化，但位置和宽度保持稳定。

| 当前状态 | 主操作 | 次操作/按需入口 |
| --- | --- | --- |
| 正在生成 | 暂停或等待，不允许编辑 | 查看真实步骤、关闭“跟随生成” |
| 本地稿有修改 | 同步摘要并复检 | 保存草稿、查看版本 |
| 有修订候选 | 接受修订 | 拒绝、查看差异、重新生成候选 |
| 有写回提案 | 接受/处理写回 | 拒绝提案、查看来源与冲突 |
| 全部通过 | 确认定稿 | 查看质量报告和交付影响 |

| 组件 | 目标设计 | 关键约束 |
| --- | --- | --- |
| 章节导航 | 卷/章、状态、字数、搜索 | 切章保存每章滚动位置和光标；恢复或 Busy 时禁止切换 |
| 正文稿纸 | 最大可编辑表面、保存/版本状态 | 流式只读；完成后可编辑；字号和行宽适合长时间阅读 |
| 流式跟随 | 当前生成位置、开关、回到底部 | 用户主动上滚后停止抢滚；显示“回到生成位置”；Reduced Motion 直接追平块内容 |
| 选区工具条 | 改写、扩写、压缩、换风格 | 预留固定槽或使用不遮挡正文的浮层；出现时不推动稿纸高度 |
| Quality Finding | 问题、证据、位置、修复动作 | Gutter 标记或定位按钮；显示全部/剩余数量；打开 finding 不调用 Provider |
| 修订 Diff | 原文、候选、变化范围 | 保持同一选区和版本签名；接受后标记摘要待同步 |
| 版本历史 | 时间、来源、版本摘要、恢复 | 恢复期间锁定关闭与切章；恢复创建新版本，不做静默回退 |
| 写回提案 | 人物、正式事实、伏笔的变更与冲突 | 使用作家语言；“Canon”和内部事件名不作为主界面文案 |

正文流式显示按句子或短行做 120-180ms 一次淡入，不使用逐字跳动、模糊或无限 RAF。`useStreamReveal` 追上目标后必须停止；页面隐藏、内容积压或 Reduced Motion 时直接追平。

完整 Context Packet、人物/世界详情、质量报告、版本历史和写回冲突均按需打开；右栏以当前质量和 Wiki 为主，不再常驻全部运行信息。已有写回提案时不重复列出同一 Wiki 摘要。

移动端正文全宽；章节导航改为下拉或底部 Sheet；选区工具改为底部面板；质量、Wiki、上下文和历史使用全屏 Sheet。打开、选择、定位、切章和查看历史不调用 Provider；只有明确“生成修订候选/换一稿”可以发起生成。

#### 验收

- 运行观测不挤压正文。
- 刷新后从最后稳定提交点恢复。
- 已落盘章节不会因生成重试被重复覆盖。
- 用户能追溯每个质量问题和 Wiki 事实的来源。

### 8.7 AI 封面

#### Artifact

- `brief`
- `visual_keywords[]`
- `composition`
- `copy_suggestions[]`
- `prompt`
- `candidates[]`
- `selected_candidate_id`

#### 用户决策

- 哪个真实候选最符合 Brief、文案和构图要求。
- 是否调整方向或 Prompt 后重新生成。
- 当前资源是否满足导出尺寸、格式和可访问性要求。

#### 写回与下一阶段依赖

- 保存选中候选 ID、真实资产位置、Prompt、Brief、构图/文案元数据和资源校验结果。
- Preview 切换不改变正式选择；只有明确“设为当前/确认封面”才更新选择状态。
- Export 只消费已保存且可读取的真实资产；CSS Fixture、失败槽位和仅预览索引不得满足导出门槛。

#### 目标布局

- 大尺寸真实候选是主工作面，使用稳定 2:3 画框。
- 候选缩略 Rail、选中状态和失败状态紧邻主图。
- 默认单图用于检查细节；用户主动进入“并排比较”时，桌面才显示 2-3 个等比例真实候选。
- Brief、Prompt 和重生成方向进入紧凑 Inspector 或 Dialog，不与封面争夺面积。
- 标题、裁切和文案安全区作为可开关叠层，不直接修改图片。
- 导出就绪度并入主工作台，不保留重复的右栏质量摘要。

#### 组件与交互细化

| 组件 | 状态 | 过渡与约束 |
| --- | --- | --- |
| 主候选画框 | Skeleton、加载、成功、失败、选中 | 成功图片在解码完成后 180-240ms Crossfade；失败保留原尺寸和重试 |
| 候选缩略 Rail | 可预览、正式选中、失败 | 预览索引与正式选择分离；定稿后仍可只读预览其他候选 |
| 并排比较 | 2-3 个真实候选、统一安全区和选择动作 | 用户主动打开；无自动播放/3D 翻转；每列固定 2:3，独立查看大图 |
| 安全区叠层 | 关闭、裁切线、标题安全区 | 80-120ms 透明度变化；不遮住主要人物或重要文案 |
| 色板 | 真实候选提取的颜色 Swatch | 使用色块和文本值，不用 CountUp 或动态图表 |
| Brief 摘要 | 题材、气质、构图、文案、禁忌 | 首屏只显示精简摘要；完整编辑进入 Dialog |
| Prompt 编辑 | 当前 Prompt、脏态、保存态 | 实时回写与“保存”只能保留一种明确持久化语义 |
| `StageFinalizeTray` | 次“重生成”、主“确认封面” | Deep 人工确认；Fast/Balanced 不新增阻断闸门，但可回看替换 |

候选加载、失败和选择必须逐项来自真实资产状态，不能固定显示“候选 2”或“资产待选”。CSS 抽象海报只能作为明确空态，不能伪装成模型结果；Demo 使用可检查的本地候选图片。

移动端主候选全宽，缩略图横滑或使用有上一张/下一张、页码和方向键的二维 Carousel，Brief/Prompt 进入底部 Sheet，确认栏固定底部。候选切换只在画框内部 Crossfade，不自动播放、不推动布局，不添加 Spotlight、3D 倾斜或持续辉光。

状态固定为：未生成 -> 候选生成中 -> 部分成功/部分失败 -> 可预览 -> 已选择 -> 资源校验中 -> 可确认/已确认。生成新候选时保留已成功旧图，只更新目标槽位；错误提供单项重试，不清空其他候选。

#### 验收

- 图片不被过度裁切、模糊或暗化。
- 封面标题与图像内容不重叠。
- 选中结果、Prompt 和来源元数据一起保存。
- 不展示人物关系、Wiki 和正文质量全家桶。

### 8.8 导出

#### Artifact

- `manifest[]`
- `formats[]`
- `chapters[]`
- `metadata`
- `validation`
- `package_status`

#### 用户决策

- 导出哪些章节、哪种格式和哪些元数据。
- 当前校验问题是否已经解决。
- 下载哪个不可变版本，并如何验证它对应当前快照。

#### 写回与终态

- 写入不可变 Manifest、Export Receipt、源快照 ID、Artifact 签名、章节选择、格式、文件大小和 SHA-256。
- Export 没有“继续下一创作阶段”或生成 Checkpoint；成功后保持在交付页，可重新下载或查看历史。
- 修改选择、格式或元数据只产生新的待校验配置，不修改旧 Receipt 和旧文件。

#### 目标布局

- 主区为章节选择 Ledger、格式 Segmented Control、元数据和包结构清单。
- 校验结果作为与具体章节、封面、事实冲突和元数据关联的状态行。
- 包名、大小、源快照、SHA-256 和 Receipt 作为紧凑交付摘要，不重复右栏质量面板。
- 底部决策栏提供生成/下载、查看 Receipt 和历史导出。

#### 组件与交互细化

| 组件 | 交互 | 真实性约束 |
| --- | --- | --- |
| 章节选择 Ledger | Checkbox、全选、清空、状态筛选 | 生成开始时冻结选择快照；Busy 期间所有选择入口一致锁定 |
| 格式选择 | Markdown/JSON/ZIP 等服务端真实支持项 | 不按章节数偷偷替用户决定；不支持项明确禁用原因 |
| 元数据编辑 | 包名、作者、标题、版本说明 | 修改后立即使旧校验失效，重新生成前显示待校验 |
| Validation 列表 | success/warning/error、对象、修复入口 | 使用作家语言映射后端 Key；删除 `return` 等内部调试行 |
| 生成进度 | 校验、生成、落盘、Receipt 等真实事件 | 无真实步骤时使用中性 Spinner，不伪造百分比和完成项 |
| 下载与 Receipt | 文件名、大小、哈希、源快照、生成时间 | 同一 request ID 重试复用同一不可变文件；UI 选择变化不改写旧收据 |
| 结果反馈 | Ready、失败、需要修复 | 错误保持可复查，不只显示 1.5 秒 Toast；失败不能使用成功勾图标 |

主操作在未生成时为“生成并下载”，生成成功后变为“重新下载”，宽度保持稳定；次操作为查看 Receipt/历史版本。选择变化 -> 校验失效 -> 生成中 -> Receipt 落盘 -> 下载就绪/失败必须有可追溯状态。

移动端保留 Checkbox 章节 Ledger，包摘要固定在选择区下方，完整 Manifest 和 Receipt 进入全屏详情。删除固定 Manifest/校验/下载包 Chips、技术性成功说明和重复下载预览。

状态固定为：待校验 -> 校验中 -> 需要修复/可生成 -> 生成中 -> 可下载/失败。失败保留全部用户配置并提供重试；成功只播放一次状态确认，不使用彩带、庆祝粒子或自动跳转。

#### 验收

- 用户可以确认实际导出的章节和格式。
- 校验错误定位到具体文件、章节或元数据。
- 下载动作产生真实文件。
- 完成后留在导出页，不自动跳回 Info 或配置页。

### 8.9 极速/平衡自动生产 Cockpit

Cockpit 是自动模式的事实工作台，不是缩小版阶段详情页集合。

#### 模式边界

- 极速：配置和运行都留在单页 Cockpit；无阶段人工闸门，失败后解释原因并提供重新开始或查看稳定产物。
- 平衡：Info 在标准工作台完成定稿，随后进入 Cockpit 自动运行；后续阶段只通过只读 Dialog/Sheet 查看，不开放独立阶段路由。
- Deep 不使用自动 Cockpit 代替阶段工作台。

#### 目标布局与组件

| 区域/组件 | 展示 | 交互与动效 |
| --- | --- | --- |
| 阶段 Rail | 当前、完成、等待、失败阶段 | 当前指示器 180ms 移动；完成只播放一次状态高亮；点击只选中摘要，不跳转未授权路由 |
| Artifact Stream | 当前阶段真实摘要、最近稳定产物 | 新块 140-180ms 淡入；已恢复内容不重复播放；不显示原始 delta 墙 |
| 运行摘要 | 当前动作、预算预警、恢复状态、下一步 | 只显示真实 SSE/Run State；无事件时保持中性等待 |
| 运行日志 | 面向用户的少量关键事件 | AnimatedList 只用于最新低频记录；不对长历史逐行 Stagger |
| 只读详情 | 当前/已完成 Artifact | 全局 Dialog/Sheet；打开和切换不调用 Provider，不暴露编辑假象 |
| Variant Compare | Balanced 用户主动请求的版本对比 | 与 Deep 换稿候选分离；费用/影响明确；完成后回到 Cockpit |

未启动时 Wiki、质量和运行详情显示明确禁用原因，不能保留可点击但无动作的入口。运行中最多保留当前节点、必要 Spinner 和流式光标三个小型循环；背景、日志行、节点和游标不得同时脉冲。

### 8.10 创作历史与恢复

历史不是装饰性时间线，而是用户查找 Run、确认状态、查看稳定快照、恢复失败链路和重新下载交付包的事实入口。

#### 目标布局

- 左侧固定宽度历史列表，提供项目、状态、模式、日期筛选与搜索。
- 右侧优先展示运行摘要、当前/最终 Artifact、稳定快照和 Export Receipt，不让三个大数字占据主要面积。
- 移动端列表与详情分两层，返回后保持搜索、筛选和滚动位置。

#### 组件与交互细化

| 组件 | 目标行为 | 约束 |
| --- | --- | --- |
| 历史搜索与筛选 | 防抖本地/服务端查询、清除条件、空结果 | 24 条以上仍可高效定位；筛选变化不关闭抽屉 |
| 历史行 | 项目名、短 Run ID、状态、阶段、更新时间 | Active 与下一行有清晰分隔；完整 ID 通过复制按钮获取 |
| 详情摘要 | 当前状态、失败原因、最近稳定点、下一动作 | Detail 切换 120ms Crossfade；固定详情区避免高度跳动 |
| 快照列表 | 时间、阶段、签名摘要、可恢复性 | 只允许恢复服务端认可的最新稳定点；操作前解释影响并确认 |
| 导出记录 | 格式、章节、大小、哈希、源快照 | 重新下载旧不可变文件，不根据当前 Run 状态重新生成 |
| 状态操作 | 打开、继续、恢复、重新下载 | 每个状态只有可执行动作；完成 Run 不伪装成可继续 |

恢复成功后保持暂停，只有用户显式“继续创作”才调用 `/resume`。查看历史、切换详情、预览快照和复制 ID 均不得触发 Provider 或恢复执行。

### 8.11 设置与知识库管理

Settings 继续使用现有 Radix Dialog/Sheet 的焦点、滚动锁和关闭生命周期，但目标信息架构从四个 Tabs 改为单页 `SettingsOverview`。外部动画组件不得替换可访问性基础。

#### 设置组件

| 组件 | 目标行为 | 必修问题 |
| --- | --- | --- |
| Settings Overview | 创作设定、参考与资料、创作方式、AI 服务、输出偏好、阶段例外、自动保护摘要 | 每区 2-4 个有效摘要和一个动作；局部编辑关闭后恢复滚动/焦点；不保留四个平级技术 Tab |
| Provider Manager | Profile 摘要行 + 局部编辑 Sheet | Provider 生命周期只存在一处；文案与 SQLite Secret/环境变量真实实现一致 |
| 密钥保存 | 显示/隐藏、来源、最后更新、清除 | 禁止重复并发提交；不在状态提示中回显密钥 |
| 检查连接 / 同步模型 | 两个独立命令，明确范围、Busy、成功、失败 | 与保存互斥或串行；连接成功不承诺完整结构化生成成功 |
| 阶段例外 | Overview 显示数量/阶段；具体设置回到 Stage Inspector 高级区 | 默认模型不重复编辑；提供恢复默认和影响说明 |
| 自动保护 | 自动保存、运行前检查、资产校验状态行 | 固定能力不显示 `checked + readOnly` Checkbox，也不伪装为可关闭 Switch |
| 局部编辑操作 | 自动保存或“取消/保存”选择一种一致合同 | Dirty、Saving、Saved、Error 状态稳定；关闭前有脏态保护 |

Settings 字段唯一归属：Story Brief 回到 Planning/Brief；参考资料回到 Knowledge；Provider Profile 和默认模型归 AI 服务；阶段模型只作为 Stage Inspector 的例外；系统固定能力只读展示。普通界面使用“AI 服务、默认生成模型、阶段例外、自动保护、检查连接、同步可用模型”等用户语义，Provider、Stage ID、Output Key 和 Memory 原始字段仅在高级诊断中出现。

#### 知识库组件

| 组件 | 目标行为 | 状态与反馈 |
| --- | --- | --- |
| 上传 Dropzone | 拖放、选择文件、格式/大小限制 | 借鉴 Aceternity File Upload 的交互机制，但压缩为工作台密度；键盘可触发 |
| 上传队列 | 文件名、大小、真实进度、成功/失败 | 失败可重试；关闭弹层不能让用户失去后台进度 |
| 文档 Ledger | 文档、来源、片段数、状态、更新时间 | `chunks/parser/local-hybrid/Docling` 等进入技术详情，不占主列表 |
| 删除操作 | 图标按钮、明确 `aria-label` | 二次确认或短时撤销；Busy 防重复；错误保持可见 |
| 来源检查 | 文件/URL、索引状态、打开原文 | 参考 URL 必须可打开，不能只显示不可操作的文本 |

### 8.12 运行观察、人物图谱、质量与 Wiki

观察组件必须服务当前 Artifact 决策，并通过全局 Sheet/Dialog 展开详情。它们不是每页同时常驻的“仪表盘”。

- 人物图谱：Canvas 负责关系概览，同时提供可键盘访问的节点/关系列表。选择节点打开有 `role="dialog"`、焦点陷阱、Escape 和焦点恢复的全局详情。
- 质量面板：阶段页优先显示当前阶段或当前章节问题，全 Run 累计信息降为次级。Finding 展示证据、位置和修复动作，详情不在右栏原地展开并推动其他面板。
- Wiki 面板：主界面使用“正式事实”“待写回”“冲突”等作家语言，原始事件名和内部字段进入技术详情。事实详情复用全局 Sheet，不保留另一套无焦点管理的 Portal。
- 世界观面板：运行态实现归入 `running/insights` 边界，不继续从 `planning/insights` 跨域复用。
- 打开图谱、质量、Wiki、世界观详情只读取当前状态；不得触发恢复、重连、生成或写回。
- 图谱数据变化可一次性补间节点位置；静止后立即停止 RAF，不保留力导向持续漂移作为装饰。

### 8.13 全局恢复、预算、熔断与人工介入

这些状态必须压过普通阶段动效，但不能用全屏装饰遮罩掩盖真实原因。

| 状态 | 首要信息 | 主操作 | 禁止行为 |
| --- | --- | --- | --- |
| 可恢复失败 | 错误分类、影响阶段、最后稳定点 | “恢复到稳定点”或“继续创作” | SSE 重连自动调用 Provider |
| 熔断打开 | 连续失败次数、停止原因、建议处理 | 修改配置/返回设置/重新开始 | 自动倒计时后重跑 |
| 预算预警 | 使用范围、剩余额度、受影响阶段 | 调整预算或继续当前已授权步骤 | 大面积闪烁、持续警报动画 |
| 预算耗尽 | 被阻止的调用、当前稳定产物 | 调整限制/导出已有结果 | 先请求 Provider 再补记超限 |
| 合同错误 | 缺失字段、解析问题、可重试性 | 查看问题/重新生成明确范围 | 展示原始 JSON 作为用户修复界面 |
| 写回冲突 | 既有事实、新提案、来源和选择 | 保留既有/采用新值/拒绝提案 | 未选择时允许接受 |

恢复面板使用持久 Inline Alert 或全局 Dialog；错误不会自动消失。用户查看原因、切换详情和返回历史不触发重试；只有显式命令才能改变 Run。Reduced Motion 下状态立即切换，错误语义不依赖抖动、颜色或动画。

## 9. 横切系统目标

### 9.1 知识库

职责：用户提供的外部依据和项目资料。

目标能力：

- 文件、公开链接和检索摘要统一入库。
- 文档切块带来源、页码或 URL。
- 检索结果可以回溯原文。
- 配置和 Info 阶段可见，后续通过 Header 或上下文入口访问。
- 不承担 Canon 写回和质量判定。

### 9.2 世界观

职责：创作世界的规则、地点、组织、限制和社会结构。

目标能力：

- 世界观锚点具有稳定 ID。
- 后续写回必须引用已有锚点或明确创建新锚点。
- 区分硬规则、可变状态和未确认提案。
- 所有变更保留阶段和章节来源。

### 9.3 人物关系网

职责：人物实体、关系和关系随故事推进的变化。

目标能力：

- 人物和关系边使用稳定 ID。
- 关系变化记录发生阶段和章节。
- 区分基础关系、当前关系和历史变化。
- 图谱负责浏览和选择，详细编辑进入结构化 Dialog。

### 9.4 Wiki 事实账本

职责：维护当前故事中已经成立的事实和未闭合承诺。

目标事实类型：

- 人物身份和状态。
- 地点和组织状态。
- 世界硬规则。
- 物品归属和状态。
- 事件和时间线。
- 人物知道什么。
- 伏笔投放、推进、回收和延后。
- 章节摘要和连续性约束。

Wiki 不是普通 Markdown 归档，也不是知识库的别名。

### 9.5 质量阀门

职责：判断产物是否通过、可修订或必须阻断。

质量结果必须包含：

- `status`: pass/revise/block。
- `dimension`：问题维度。
- `severity`：严重程度。
- `message`：面向创作者的说明。
- `evidence[]`：具体字段、章节和事实来源。
- `revision_instruction`：可执行修订指令。
- `recheck_result`：修订后的复检结果。

### 9.6 阶段与洞察面板可见性矩阵

| 表面 | 人物 | 世界观 | 质量 | Wiki | 运行日志 |
| --- | --- | --- | --- | --- | --- |
| Planning | 不显示 | 不显示 | 不显示 | 不显示 | 不显示 |
| Fast/Balanced Cockpit | 当前阶段摘要，按需 | 当前阶段摘要，按需 | 阻断/预警优先 | 当前阶段摘要，按需 | 关键事件入口 |
| Info | 关系图常驻 | 摘要常驻 | 仅真实阻断 | 不显示 | 不显示 |
| Summary | 图谱常驻 | 与质量切换 | 与世界观切换 | 不常驻 | 详情入口 |
| Outline | 图谱常驻 | 与质量切换 | 与世界观切换 | 不常驻 | 详情入口 |
| Detail | 图谱常驻 | 紧凑入口 | 紧凑入口 | 当前章主观察区 | 详情入口 |

### 9.7 提案、预览、正式写回与事实状态语法

| 语义 | 文案示例 | 视觉 | 可执行动作 |
| --- | --- | --- | --- |
| 当前稿预览 | “定稿后将写入人物关系” | 中性边框、草稿标记 | 编辑、放弃、继续审阅 |
| 待写回提案 | “有 3 项事实待决定” | 警示但不使用错误色 | 接受、拒绝、处理冲突 |
| 已授权待提交 | “将在本次定稿时写入” | 明确授权标记 | 撤回授权、定稿 |
| 正式写回 | “已写入正式事实，来源：第 4 章” | 一次性成功反馈 | 查看来源、查看版本 |
| 冲突 | “既有事实与新提案不一致” | 错误/阻断语义 | 保留既有、采用新值、拒绝 |
| 已替代 | “已由第 8 章的新事实替代” | 弱化历史状态 | 查看时序和来源 |

颜色、图标和动效只能增强这些文本语义，不能让“提案”看起来像“已同步”，也不能将保存草稿等同于正式写回。

### 9.8 洞察详情与图谱交互合同

- 所有洞察详情使用同一 `RuntimeInsightSheet`/`FocusedDialog` 壳层，统一层级、焦点、脏态、滚动和退出动画。
- 右栏只展开摘要，不在原位无限展开详情；详情打开后主 Artifact 尺寸保持稳定。
- 图谱节点、质量 Finding、Wiki 事实和世界锚点使用稳定 ID，跨视图选择同一对象时保持身份一致。
- 图谱 Hover 可显示轻量标签，但点击/键盘选择才打开详情；Touch 使用等价 Tap 路径。
- 洞察数据更新只播放一次局部高亮；历史恢复后不重放所有旧事件动画。
- 技术详情可显示事件、签名和来源 ID，但默认创作视图只使用面向作者的语言。

## 10. 章节十步运行管线

### 10.1 目标步骤

| 步骤 | 输入 | 输出 | 提交性质 |
| --- | --- | --- | --- |
| 1. 章节定位 | 细纲、进度 | 当前章节目标 | 临时 |
| 2. 上下文装配 | Wiki、人物、世界、近期摘要 | Context Packet | 可重建 |
| 3. 执行剧本 | 章节蓝图 | Scene/Beat 执行计划 | 可重建 |
| 4. 正文生成 | Context Packet、执行计划 | 流式草稿 | 临时 |
| 5. 合同校验 | 草稿、结构合同 | 校验结果 | 临时 |
| 6. 章节落盘 | 通过草稿 | 章节版本 | 稳定 |
| 7. 文风/连续性审计 | 章节版本、Canon | 质量报告 | 稳定附属 |
| 8. 章后处理 | 章节版本 | 摘要、事实和伏笔提案 | 稳定附属 |
| 9. 张力评分 | 章节和全书节奏 | 张力记录 | 稳定附属 |
| 10. 结算 | 全部结果 | Checkpoint、下一章输入 | 稳定 |

### 10.2 重试规则

- Provider 超时允许有限重试。
- 结构化合同失败允许修复或重新生成。
- 稳定落盘之后不得重新执行生成步骤覆盖正文。
- 章后处理失败不能删除已落盘章节，应进入待修复队列。
- 每类失败必须有独立重试计数。
- 达到预算或重试上限后触发熔断并等待用户处理。

### 10.3 成本规则

- 每个阶段和章节都有生成预算。
- 候选、修订和模型评审分别计费。
- 平衡模式未主动请求对比时不生成额外候选。
- 失败重试计入成本并在 UI 可见。
- 超预算前预警，超预算后停止，不允许后台无限继续。

## 11. Canon 与记忆数据模型

### 11.1 事实模型

目标事实至少包含：

```text
Fact
  id
  subject_id
  predicate
  value
  value_type
  scope
  status
  valid_from_stage
  valid_from_chapter
  valid_to_chapter
  source_artifact_id
  source_artifact_version
  source_excerpt
  confidence
  created_at
  supersedes_fact_id
```

### 11.2 状态类型

- `proposed`：模型或用户刚提交，尚未成为 Canon。
- `canonical`：当前有效事实。
- `superseded`：被后续事实替代，但保留历史。
- `rejected`：明确拒绝，不应再次自动写入。
- `conflicted`：与现有 Canon 冲突，等待处理。

### 11.3 事实写回流程

```text
阶段产物/正文
  -> 提取写回提案
  -> 结构和实体校验
  -> 与 Canon 冲突检查
  -> 自动通过 / 人工确认 / 质量阻断
  -> 写入 Canon
  -> 生成来源和版本记录
  -> 进入下一阶段 Context Packet
```

### 11.4 Context Packet 优先级

1. 不可违背的硬规则和阻断警告。
2. 当前章节涉及人物和关系的当前状态。
3. 当前场景地点、组织和物品状态。
4. 上一章和最近章节摘要。
5. 当前未闭合伏笔和章节承诺。
6. 与本章语义相关的历史片段。
7. 风格参考和可选背景资料。

Token 超预算时从低优先级向高优先级裁剪，硬规则和阻断警告不得被截断。

## 12. Artifact 版本与检查点

### 12.1 Artifact 版本

每次以下操作都应形成新版本：

- 模型首次生成。
- 用户保存编辑。
- 换一稿产生候选。
- 用户选择候选。
- 质量修订完成。
- 用户确认定稿。

版本记录至少包含：

- Artifact ID。
- 阶段 ID。
- 版本号。
- 内容摘要或内容引用。
- 来源操作。
- 父版本。
- 用户/模型来源。
- 创建时间。
- 确认状态。

### 12.2 检查点

检查点不等于用户定稿。

- `generated_checkpoint`：产物生成完成。
- `confirmed_checkpoint`：用户完成定稿。
- `chapter_committed_checkpoint`：章节稳定落盘。
- `run_completed_checkpoint`：全链路完成。

### 12.3 恢复

恢复必须还原：

- 当前模式。
- 当前阶段和路由。
- 已完成阶段。
- Artifact 当前版本。
- 等待确认状态。
- 暂停状态。
- 当前章节和步骤。
- 已消费事件位置。
- 剩余预算和重试计数。

## 16. 外部 UI 与动效组件采纳方案

### 16.1 采纳原则与许可证门禁

Aceternity UI、React Bits 和 Uiverse 提供的是可参考的组件与交互模式，不是 Yotsuba Ink 的新设计系统。Anime.js 是条件性动画工具，不是第二套全局动画运行时。

每个候选必须依次通过六道门槛：

1. 解决明确的用户问题，而不是因为效果“好看”。
2. 不改变阶段 Artifact、用户决策、写回目标、模式权限和路由合同。
3. 能改造成当前 Radix、Token、密度、Lucide 和焦点体系。
4. 在 Reduced Motion 下可以完全停用，且功能和状态仍然成立。
5. 不制造持续 CPU/GPU 开销、布局抖动、首屏依赖或额外网络请求。
6. 来源、版本、许可证、作者声明和改造范围已经登记。

“免费组件”只表示获取成本，不自动代表任意商用、再分发或无署名复制。许可证未核验时，只能把交互思想写进计划，禁止复制源码进入产品。

### 16.2 来源、版本与许可证登记

| 来源 | 当前核验结论 | 代码采纳状态 | 进入实现前的动作 |
| --- | --- | --- | --- |
| Aceternity UI | Item Licence 允许 Free Item 用于商业终端产品并修改；但官网 Terms 对一般材料有更严限制，且第三方内容另行许可 | Conditional | 只用明确 `proComponent:false`/可复制的 Item；保存 Item、Licence、Terms 页面快照，禁止复制 Pro Block、模板和官网视觉资产 |
| React Bits | 自定义 `MIT + Commons Clause`；可用于商业终端产品并修改，必须保留声明；禁止单独/打包出售、再许可、再分发组件或衍生组件库 | Conditional | 按组件记录来源、Commit 和声明；只进入本产品，不能形成对外 UI 包 |
| Uiverse `uiverse-io/galaxy` | Galaxy 仓库内元素为 MIT；不能据此推断主站所有新投稿均为 MIT | Allow from verified repo | 只从可定位的 Galaxy 文件提取微样式，记录文件、作者、Commit 并保留 MIT 声明 |
| Anime.js | 官方仓库标准 MIT；本轮核验版本 v4.5.0，当前项目尚未安装 | Conditional by architecture | 只有隔离场景评审通过后安装，记录版本、包体、Scope、`revert/cancel` 和回退方案 |
| PlotPilot | 仅作流程和产品研究，源码存在额外使用限制 | No code copy | 保留能力对照，不复制实现代码 |

每个实际引入项建立清单：`source_url`、`source_version`、`license`、`author`、`copied_or_reimplemented`、`target_component`、`runtime`、`keyboard_support`、`reduced_motion`、`bundle_delta`、`fallback`。

### 16.3 Allow / Conditional / Reject 总矩阵

| 决策 | 定义 | 例子 |
| --- | --- | --- |
| Allow | 交互机制可由现有 CSS/Motion 独立实现，产品价值明确 | 短淡入、稳定 Tab 指示器、按钮按压、图片 Crossfade |
| Conditional | 只有真实数据、许可证、性能、键盘和降级全部通过才可使用 | 多步 Loader、文件上传动效、AnimatedList、SVG 图谱时间线 |
| Reject | 与专业长文工作台冲突，或只有装饰价值 | Aurora、粒子、跟随光标、3D 倾斜、无限跑马灯、文字解密 |

任何 Conditional 组件如果需要改变现有状态事实源、引入第二套基础控件或新增持续动画，自动降级为 Reject。

### 16.4 Aceternity UI 候选

| 候选 | 目标业务组件 | 决策 | 采纳方式 |
| --- | --- | --- | --- |
| Animated Tabs | Settings、Inspector、Summary/Outline 切换区 | Allow mechanism | 只借共享 Active Indicator；保留 Radix/ARIA 语义和 DOM 顺序，拒绝把选中项移到首位、3D 内容堆叠和长弹簧 |
| Animated Modal | `FocusedDialog`、候选方向、快照详情 | Reject direct / allow rhythm | 保留现有 Overlay、焦点和滚动锁，只借 `opacity + translateY(8-12px)`；拒绝 `scale(.5)`、RotateX、背景 Blur 和自制 Body Lock |
| Stateful Button | 启动、保存、定稿、生成导出 | Allow mechanism | 受控 `idle/pending/success/error`；Pending 宽度固定、`aria-busy`、防重；Success 只由真实服务端响应触发 |
| Multi Step Loader | 章节十步管线、真实导出步骤 | Conditional | 只借完成/当前/等待清单；删除源码计时循环，每一步映射 SSE/Run State；无真实事件时改中性 Spinner |
| File Upload | 知识库上传队列 | Conditional | 压缩装饰面积，加入格式、大小、真实进度、失败重试和键盘入口 |
| Expandable Cards | 历史摘要、Artifact 只读详情 | Conditional | 桌面列表/详情布局优先；只借展开关系，不将页面变成卡片墙 |
| Focus Cards / 3D Card | 无必要场景 | Reject | 会弱化其他信息或引入倾斜，不适合高密度工作台 |
| Background Beams / Meteors / Vortex | 无业务场景 | Reject | 持续装饰、视觉噪声和性能成本均不成立 |

### 16.5 React Bits 候选

| 候选 | 目标业务组件 | 决策 | 采纳方式 |
| --- | --- | --- | --- |
| FadeContent / AnimatedContent | Tab、只读详情、局部 Artifact 切换 | Reject direct / allow concept | 原实现依赖 GSAP/ScrollTrigger、长位移和可选 Blur；使用现有 Motion 重写为 160-240ms、3-12px、无 Blur |
| AnimatedList | 最新运行事件、质量 Finding、写回记录 | Reject direct / allow concept | 只借滚动边缘提示和选中项滚入视口；原实现会接管 Window 键盘并反复缩放列表，本地语义列表只对可见新增项轻淡入 |
| Stepper | 配置完成度、真实阶段结算 | Reject direct / allow motif | 只参考连接线与完成标记；本地 Button/Tab 语义和业务状态独立实现 |
| CountUp | 最终字数、导出大小、一次性结算数据 | Conditional | 数值稳定后播放一次；实时 Token、错误数和频繁变化指标直接更新 |
| Carousel | 移动端封面候选 | Conditional concept | 只借拖拽阈值和页码；无自动播放、无 3D 旋转，必须提供上一张/下一张和方向键 |
| GradualBlur | 长列表滚动边缘 | Replace | 使用低成本静态渐隐遮罩，不引入大面积动态 Blur |
| GlassSurface | 极小型选区工具条 | Reject | SVG Displacement/Filter 成本、兼容降级和装饰性不值得引入 |
| Dock | 无默认场景 | Reject | Hover 放大和图标导航会降低操作可预测性，现有 Header/工具轨更合适 |
| SpotlightCard / MagicBento | 无默认场景 | Reject | 容易形成展示站卡片墙，封面候选也只需边框、选择和真实图片 |

React Bits 当前最有价值的是过渡机制，不是默认紫色、超大圆角、玻璃和展示型布局。

### 16.6 Uiverse 微交互候选

Uiverse 只用于提炼单个控件的状态细节，不能整页拼装；可复制代码仅来自 Galaxy 仓库内能够定位并登记的 MIT 文件。

- Button：可借按压、Spinner 对齐和 Success 图标进入方式；颜色、尺寸、DOM、文案和状态机全部本地化。
- Input/Textarea：可借 Focus 边框、错误状态和清除按钮布局；不使用浮夸霓虹或占位符位移动画干扰长文输入。
- Checkbox/Switch：可借清晰选中反馈；保持原生/ARIA 语义和 44px 移动端触控区。
- Loader：只保留小型 Spinner、Skeleton Shimmer 或真实 Progress；拒绝多环、太空、液体和长时间循环表演。
- File element：可借文件行状态与移除操作；不使用占据首屏的大型 Dropzone 动画。
- Tooltip/Menu：只借阴影、边界和指向关系；定位、Focus 和 Escape 继续使用成熟基础组件。

### 16.7 Anime.js 条件性使用

当前 `motion@12.40.0` 已覆盖 React 状态动画，Anime.js 暂不安装。只有同时满足以下条件才进入技术评审：

- 场景是复杂 SVG 路径、Canvas 数据过渡或三步以上一次性时间线。
- Motion/CSS 实现会显著增加复杂度或无法可靠清理。
- 动画仅解释真实数据变化，不驱动业务状态。
- 模块可懒加载；React 中使用 `createScope({ root })` 隔离，卸载时执行 `scope.revert()`，必要时显式 `cancel()`。
- 与 Motion 不同时控制同一元素或同一属性。

允许评估的未来场景：人物关系图在数据变更后的单次节点/边重排、卷节奏折线的单次路径绘制、复杂 SVG 写回路径的短时间说明。

禁止使用 Anime.js 的场景：路由、阶段切换、Dialog、Sheet、Tabs、Button、Toast、Loader、流式正文、SSE 进度、确认/写回/恢复状态和任何持续背景。

### 16.9 全局动效架构与时间 Token

现状审计：30 个 TSX 直接使用 `motion/react`；CSS 约有 71 个 Keyframes、96 条 Animation 声明和 56 条 Infinite，且 Motion/流式 RAF 尚未被统一 Reduced Motion 控制。Phase 8 必须先建立清单和所有权，再逐页替换，不能直接批量删除多代样式。

职责划分：

- CSS Transition：颜色、边框、背景、Focus Ring、Button Press 等微反馈。
- `motion/react`：React 挂载/卸载、布局关系、Dialog/Sheet、Tab 内容、阶段内容和候选切换。
- Anime.js：仅 16.7 的隔离复杂场景。
- 业务状态：只来自用户命令、Reducer、Artifact 和服务端事件；动画只消费状态，绝不通过 `setTimeout` 制造完成。

统一时间与幅度：

| 场景 | 时间 | 属性和幅度 |
| --- | --- | --- |
| Hover/颜色反馈 | 120ms | 背景、边框、文字；行和卡片不抬升 |
| Button Press | 80ms 入 / 90ms 回 | 最大 `scale(.98)`，推荐 `.985`；不改变尺寸 |
| Focus | 0ms | 2px `focus-visible` Ring 即时出现 |
| Active/Selected | 160-180ms | 指示器或内描边；内容位置稳定 |
| Tab Indicator | 180-220ms | Transform 平移；不改变 Tab 宽度 |
| Tab Content | 160-180ms 入 / 100-120ms 出 | Opacity + 最多 3px 位移 |
| Dialog Backdrop | 140-180ms | 只动画 Opacity，不动画 Blur |
| Dialog Surface | 180-240ms 入 / 120-160ms 出 | Opacity、Y 8-12px、Scale .985 |
| Side Sheet | 220ms 入 / 160ms 出 | 桌面 X 24px；移动端 Y 16px |
| Tooltip | 延迟 300-500ms，Fade 100ms | Opacity + 最多 2px；离开立即收起 |
| Toast | 160ms 入 / 120ms 出 | Y 6px；错误不自动消失 |
| 页面/阶段内容 | 180-240ms 入 / 100-140ms 出 | Opacity + X 8px；稳定 Header 不重播 |
| Streaming Chunk | 120-180ms/块 | 句子或短行 Opacity；不逐字、不模糊 |
| 状态写回 | 220-300ms 一次 | 边框/底色短暂高亮；禁止循环呼吸 |
| Spinner | 900ms Linear | 仅小型必要循环，真实 Progress 优先 |

统一缓动：Standard `cubic-bezier(.2, 0, 0, 1)`；Enter `cubic-bezier(.16, 1, .3, 1)`；Exit `cubic-bezier(.4, 0, 1, 1)`；Linear 仅用于 Spinner 和真实连续进度。

### 16.11 路由、组件切换、流式和性能合同

- 路由：Header、阶段导航和决策栏外壳保持稳定，只切换主工作区。退出 100-140ms、进入 180-240ms，总阻塞不超过 280ms。不得继续使用两个 280ms `mode="wait"` 串行并动画 Blur。
- 阶段结算：只在真实提交完成后出现，最多停留 800-1200ms；用户无需等待固定 5 秒。失败、待确认和恢复不得播放成功结算。
- Dialog/Sheet：背景和 Surface 分层退场，退出期间阻止重复触发；焦点在 Surface 完成退出后返回。
- Tabs/组件切换：只动指示器和内容，不重挂载整个工作台，不重置输入、滚动和选中对象。
- 候选：三列各自只入场一次，取消无上限 Stagger；选稿后回到单栏稿，切换本身不触发 Provider。
- 流式：追上内容后停止 RAF；用户上滚后停止自动跟随；隐藏页或积压过多时立即追平；恢复内容不重播动画。
- 图片：封面只在真实图片 Decode 成功后 Crossfade，画框、标题安全区和操作栏全程稳定。
- 图谱：只在数据变化时进行一次布局过渡，静止后停止 RAF；Canvas 同步提供可访问 Ledger。
- Static Motion：空闲状态不运行装饰循环；静态纹理、模式色内描边和一次性状态高亮替代 Aurora、Orb、Starfield、Meteor 和 Card Breathing。
- 动画只优先使用 `transform` 与 `opacity`；颜色/边框微过渡可使用 CSS。禁止在大面积元素逐帧动画 `filter`、`backdrop-filter`、`box-shadow` 和 `background-position`。

Reduced Motion 合同沿用已完成的 Phase 2.4：所有非必要 CSS/Motion/Anime 动画为 `0s/none`，状态立即切换，不采用“缩短到 80ms”的弱化方案；停止自动平滑滚动、流式 RAF、位移、缩放和闪烁。

性能预算：

- 空闲页 `document.getAnimations()` 中 Infinite 动画为 0，持续 RAF 为 0。
- 真实运行态最多 3 个小型必要循环。
- 点击后 100ms 内出现反馈，Dialog 250ms 内可操作，阶段切换总等待不超过 280ms。
- 动画引起的 Long Task 为 0；目标帧耗时不超过 16.7ms，掉帧率低于 5%，CLS 为 0。
- 动效不得触发 `/resume`、SSE 重连、Provider 请求、重复提交、正式写回或重复计费。

标准集成 Prompt：


- 运行事件新增 `provider_attempt_started`、`provider_attempt_failed`、`provider_fallback_scheduled`、`provider_attempt_succeeded` 和 `provider_fallback_blocked`。事件只包含稳定错误码、公开提示、Provider Profile ID、模型、预算操作 ID 与是否可能计费，不包含 API Key、Base URL、上游原文或请求 ID。
- Cover 候选会记录实际成功的 Provider、模型和派生 `generation_key`；同一批候选来自多个来源时，阶段汇总标记为 `mixed`，不再用主 Provider 覆盖真实来源。Provider 已返回图片但本地格式/比例/落盘校验失败时立即停止，不切换厂商。
- 零费用 readiness 把所有已启用备用来源纳入真实依赖检查；Provider 删除保护同时检查节点配置和 Stage Config 中的文本/图片备用引用。备用 Profile 缺失、禁用、类型错误、模板无效、缺 URL 或密钥都会在创建 Run 前阻断。
- 阶段“生成模型”区域新增折叠式故障转移编辑器，文本与图片分别维护顺序、Provider、模型和启用状态；切换主 Provider 会自动移除与主项冲突的备用项。全局 Settings 只继续承担 Profile 生命周期和阶段主分配，不新增脱离阶段语义的复杂路由控制台。
- 本阶段只使用 Fake Provider 验证成功切换、独立预算、不同幂等键、严格禁止结构错误切换以及图片不确定响应保护；没有再次调用余额不足的 TokenHub 文本或图片生成，也没有创建新的真实验收 Run。
- 最终自动化门禁通过：Python 3.14 后端 `206 passed / 1 skipped / 1 warning`，前端 `59 files / 201 passed`，TypeScript 与生产构建通过（`3299 modules transformed`），CSS 审计与 `git diff --check` 通过。浏览器在 `1440x1000` 和 `390x844` 完成备用项新增、启停、上移、下移和清理验收，修复窄栏内 Provider/模型控件重叠以及图标按钮点阵伪元素越界问题；两个视口均无横向溢出，截图保存在 `output/playwright/phase88a5/`。验收使用的两个无密钥临时 Provider 已删除，工作流备用配置已清空，运行历史保持原有 20 条且没有 `phase88a5` Run。

`Phase 8.8B` 更新后的启动条件：TokenHub 账户恢复可用余额，或文本/图片同时切换到已验证有额度的账号。图片 Base URL、模板、模型、密钥与零费用鉴权已经补齐，不再是配置阻塞；余额变化后只执行一次最低成本图片产物验证与一次最小文本结构化验证，两者成功后再创建唯一 Fast 验收 Run。余额变化前不得重复真实生成探针，也不得用生产 Mock、跳过 Cover 或仅生成提示词来标记完整链路通过。

- 控制台无新增错误和警告。

### 18.5 性能验收

- 空闲页面 Infinite Animation 和持续 RAF 为 0。
- 真实运行态最多 3 个小型必要循环。
- 隐藏页面停止非必要轮询和渲染。
- 人物图谱仅在可见时更新布局。
- 长章节使用增量渲染，不反复重排全文。
- 非当前阶段重型页面按需加载。
- 动画 Long Task 为 0，目标单帧不超过 16.7ms，掉帧率低于 5%，CLS 为 0。
- 点击 100ms 内反馈、Dialog 250ms 内可操作、阶段内容切换总等待不超过 280ms。
- 大面积元素不逐帧动画 Blur、Filter、Backdrop Filter、Box Shadow 或 Background Position。

### 18.6 视觉回归与证据留存

- 每个 Phase 8 子阶段开始前保存目标页面截图、动画数量和网络基线，完成后使用相同数据与视口复测。
- 截图覆盖主 Artifact、Overlay、长内容、空态、错误、Busy、选中、Focus 和 Reduced Motion，不只截默认成功页。
- 组件级截图比较设置稳定容差；流式时间、随机 ID 和真实时钟需要冻结或排除，不能通过放宽全屏阈值掩盖回归。
- 浏览器录制重点检查弹层进出、Tab、阶段切换、候选切换、正文跟随和封面 Crossfade 的卡顿与布局跳动。
- 每个子阶段保留可回滚边界；构建、测试或视觉门槛未通过时，不把后续页面继续叠加在失败基线上。

## 19. 成功指标

### 19.1 易用性

- 新用户能说清三档模式差异。
- 用户始终知道当前阶段、状态和下一步。
- 关键操作不依赖阅读技术日志。
- 错误发生后有明确恢复路径。
- 任一阶段首屏 3 秒内可以识别主 Artifact、当前决策和推进动作。
- 人工确认前可以看清写回影响，确认后可以追溯真实结果。
- 仅键盘、触屏和 Reduced Motion 均能完成对应链路。

### 19.2 创作效率

- 从进入阶段到找到主要编辑区不超过一次视觉扫描。
- 正文阶段上下文切换明显减少。
- 用户可以定位一条事实来自哪个阶段和章节。
- 局部修订不需要整章或整阶段重跑。

### 19.3 运行可靠性

- 无无限重试。
- 无重复落盘。
- 无重复写回。
- 刷新后状态可恢复。
- Token、费用和失败重试可追踪。

### 19.4 工程质量

- 普通源文件约 200-250 行。
- 重型模块不超过 300 行，除非有明确说明。
- API 路由保持薄层。
- 前端只有一套目录语义。
- 核心状态有单元和集成测试。
- CSS、Motion 和可选 Anime 场景都有明确所有者、清理和降级路径。
- 外部组件来源、版本、许可证与改造记录完整。
- UI 过渡不会产生额外业务请求、写回或计费。

## 20. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| UI 重构和真实 API 联调同时进行 | 难以定位回归 | 先冻结合同，再分层替换 |
| 继续在巨型文件中增加效果 | 样式和状态失控 | Phase 1 先拆边界 |
| 外部组件使用过量 | 性能下降、产品像展示站 | Allow/Conditional/Reject 白名单和逐组件验收 |
| 把“免费”当作许可证 | 商用、归属和再分发风险 | 来源/版本/许可证登记；未核验不复制源码 |
| Anime.js 变成第二套全局运行时 | 清理困难、状态和动画争抢 | 只允许隔离 SVG/Canvas/时间线，普通场景继续 CSS/Motion |
| 动画计时器制造业务完成 | 伪进度、伪成功和错误推进 | 动画只消费 Reducer/Artifact/SSE 状态 |
| 多代 CSS 继续叠加 | 选择器冲突和回归不可预测 | 建立消费者/所有权表后逐页收敛，不批量盲删 |
| 全局美化先于草稿安全 | 页面更顺但数据仍会丢失 | Phase 8.0 P0 门槛先完成 |
| 直接复制 PlotPilot 架构 | 产品主线漂移 | 只吸收章节运行能力 |
| Wiki 继续保存整段 Artifact | 无法做事实级冲突 | 建立结构化事实和来源 |
| 自动模式无限重试 | Token 和费用失控 | 重试上限、预算和熔断 |
| 演示回退掩盖真实错误 | 用户误以为成功 | Demo Fixture 与真实状态分离 |
| 一次性全量重写 | 长期不可交付 | 每 Phase 必须可独立验收 |

## 22. 每阶段实施前检查模板

```text
阶段：

Artifact：
- 模型返回哪些结构化字段？
- 哪些字段可编辑？
- 哪些字段必须稳定存在？

Decision：
- 用户在这里真正决定什么？
- 哪种模式需要人工确认？
- Fast/Balanced/Deep 的可见页面、只读入口和主操作是否符合路由合同？

Writeback：
- 写回世界观、人物关系、Wiki、质量还是下一阶段上下文？
- 写回是提案还是直接 Canon？

Dependency：
- 下一阶段依赖哪些字段？
- 缺失时是阻断、警告还是允许继续？

UI：
- 主工作面是什么？
- 哪些信息必须首屏可见？
- 哪些信息进入 Dialog、Sheet 或 Header 入口？
- 是否只有一个主 Artifact、一个支撑栏和一个主决策？
- 每个指标是否有真实 Artifact/Event 来源？

State：
- 加载、流式、可编辑、等待确认、已确认、失败如何表达？
- Dirty、Busy、ReadOnly、Recovery 和 Reduced Motion 如何表达？
- 打开、切换和动画是否完全不改变业务状态？

Motion：
- 使用 CSS、Motion 还是条件性 Anime.js？为什么？
- 时长、属性、退出、取消、Reduced Motion 和性能预算是什么？
- 空闲是否为零循环？

External source：
- 来源、版本、许可证、作者和保留声明是否已核验？
- 是复制代码还是独立实现交互思想？
- 键盘、触屏和无动画回退是什么？

Verification：
- 单测、合同测试、浏览器路径和视口是什么？
```

## 23. 最终 Definition of Done

本轮目标只有同时满足以下条件才算完成：

1. 三档模式的控制权差异真实生效。
2. 每个阶段围绕正确 Artifact 和用户决策设计。
3. 正文阶段形成章节树、正文、上下文三层专业工作台。
4. Wiki 具备事实、来源、版本和时序能力。
5. 质量问题可解释、可修订、可复检。
6. 运行支持稳定提交、暂停、恢复、预算和熔断。
7. 真实 API 错误不再被演示数据掩盖。
8. 前端状态只有一套事件归并事实源。
9. 前后端文件和目录满足仓库工程守则。
10. 从配置到导出存在一条通过真实 API 验收的完整小流量链路。
11. 关键 UI 在目标视口下无溢出、遮挡和控制台错误。
12. 外部组件和动效只增强状态表达，不改变产品为专业创作工作台的本质。
13. 所有阶段首屏围绕一个主 Artifact、一个支撑栏和一个主要决策组织。
14. 无假控件、伪进度、伪成功、原始 JSON、硬编码指标或装饰性运行数据。
15. Dirty/Busy/破坏性操作、切章、切对象和弹层关闭都不会造成无提示数据丢失。
16. Reduced Motion 为 `0s/none`，空闲动画和持续 RAF 为 0，性能预算通过。
17. 外部源码只有在许可证、版本和归属记录完成后才允许进入产品。
18. 纯 UI 交互不会触发 Provider、`/resume`、SSE 重连、正式写回、重复提交或重复计费。
