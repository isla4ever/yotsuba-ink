## 2. 产品需求先于视觉

每个页面必须先回答四件事，视觉只服务于这些答案：

| 页面 | 主要产物 | 用户决策 | 写回 / 下一步 |
| --- | --- | --- | --- |
| Studio | 作品、最近运行、模板摘要 | 新建、进入、归档作品 | 进入作品级规划上下文 |
| Planning | 工作流、故事起点、AI 服务、创作模式 | 补全阻塞项并启动 | 生成 run 输入，不展示运行态观测全家桶 |
| Cockpit | 同一 SSE 事件源派生的阶段状态与 Artifact 流 | 查看、恢复、进入允许的阶段 | 自动模式继续执行；不伪造进度 |
| Stage Workbench | 当前阶段结构化 Artifact | 编辑、换稿、定稿 | 按阶段合同写入下一阶段上下文 |
| Story Bible | 已正式确认的人物、世界、事实与连续性 | 检索、审阅、定位来源 | 不接收未确认草稿的假写回 |

配置态不得因为参考图有 KPI 卡就添加运行统计；运行态不得因为参考图有任务堆栈就把不同写回系统合并为一个“AI 状态”。

## 3. 图 2 的设计语言转译

### 采用

- **黑晶底座**：接近黑色的中性背景，表面以细边、顶部高光和局部透明度分层，不用大面积蓝紫渐变。
- **稿件堆栈**：把图中的层叠任务卡转译为 Info → Summary → Outline → Detail → Text → Cover → Export 的 Artifact Deck；当前阶段使用创作模式色，其余阶段保持银灰。
- **精密仪表感**：紧凑数字、窄间距标签、清晰状态点、可扫描的时间 / 用量 / 阶段位置；所有数字来自真实状态。
- **单一活动光源**：每个视图只允许当前模式色成为主强调色。极速为冷蓝、平衡为青绿、精细为紫色；危险与警告仍使用独立语义色。
- **材质差异**：主编辑面为低反射稿纸 / 面板，导航与辅助层为半透明玻璃；避免所有区域都做相同卡片。
- **短促过渡**：壳层切换、对话框、阶段选中和稿件堆栈位移使用 120-220ms，一次性完成；Reduced Motion 为 0ms。

### 不采用

- 不复制任务管理 KPI、日历甘特图、负责人和到期日等无关功能。
- 不把所有内容包成发光圆角卡，不做卡中卡。
- 不使用持续旋转、粒子、无限 shimmer、背景呼吸或鼠标追随光斑。
- 不把 3D 透视堆栈作为必需的交互控件；它是可视状态摘要，键盘和移动端必须有等价的二维阶段轨道。
- 不让绿色成为全局万能状态色；强调色由创作模式决定，完成 / 警告 / 失败有独立语义。

## 4. 页面映射

### Studio

- 左侧产品导航与作品库共用同一黑晶壳层；移动端必须有品牌、导航和新建作品入口。
- 作品卡显示书名、最近阶段、真实进度与最近活动；打开时卡片进入 `aria-busy`，失败显示页面级 toast。
- 新建作品仍以书名为第一决策；单模板不再制造第二个无意义步骤。

### Planning

- 中央 Artifact Deck 取代纯装饰图：七层分别对应真实阶段；选中层与右侧 Stage Inspector 同步。
- 右侧只显示当前阶段首屏必需字段。高级区只保留“AI 服务与模型例外”。
- `quality_policy` 和 `memory_policy` 不再由用户逐阶段编辑；只读说明其由创作模式和阶段合同派生。
- 版本比对的成本开关只在支持阶段可见，评审服务与模型继承 Provider 配置。

### Cockpit 与 Stage Workbench

- Cockpit 的中央稿件流和阶段轨使用真实 SSE；不增加假完成率或独立计时器。
- 阶段工作台保留现有 Artifact-first 布局；视觉升级集中在边框、层次、选中状态、命令区和对话框，不重写已验证的数据编辑合同。
- “保存到当前稿”“确认定稿”“正式写回”必须继续使用不同文案和状态。

## 5. 视觉令牌

- 背景：中性黑 `#070908` 到 `#0d100f`；不使用一整屏同色蓝灰。
- 表面：`surface-0` 无框底层、`surface-1` 轻玻璃、`surface-2` 编辑 / 对话框实体面；最多三层。
- 边框：1px 中性白 8%-16%，选中态混入模式色 36%-52%。
- 圆角：控件 6px，工作面 8px；仅药丸状态和分段控件使用全圆角。
- 字体：现有字体栈优先；正文可读性优先，数字使用 tabular nums；不按视口缩放字号。
- 阴影：局部内高光 + 短距离深阴影；不使用大面积彩色辉光。
- 栅格：桌面保持高密度双 / 三栏；移动端按“主动作 → 当前产物 → 辅助状态”单列重排。

## 6. W3A 实施合同

1. 后端在工作流落盘 / 执行前由 `quality_mode` 派生阶段 `quality_policy`，前端只消费派生结果。
2. Stage Inspector 首屏只展示阶段输入；高级区只展示 Provider / 模型例外、温度三档和只读预算上限。
3. 全局 Provider 备用链在 Settings 编辑，再批量投影到各阶段现有 `fallback_targets`，不更改执行合同。
4. Provider 主路径固定为“厂商模板 → API Key → 默认模型 → 保存并检查”，高级字段折叠。
5. Cover 首屏保留封面风格和候选数；固定比例改为说明，运维护栏不占首屏。
6. 设置总览只保留可操作入口；无例外时不显示伪“了解”卡片。
7. 默认工作流 reseed 比较版本与规范化内容摘要，且只覆盖 default id。

## 7. W3B 实施合同

1. Studio、Planning、Running、Bible 共享一个壳层过渡所有者；Header / 侧栏切换不再硬跳。
2. New Project Wizard 和知识库启动拦截复用 `useOverlayDialog`、统一 motion token、焦点陷阱、Esc 与焦点归还。
3. Studio Sidebar 与 Workbench Sidebar 共享键盘导航模型；Reduced Motion 禁用 smooth scroll。
4. 通用按钮 hover 降低特异性，焦点反馈只保留一个可覆盖的全局轨道。
5. fast / balanced 无阶段路由时，侧栏用一条座舱入口替代七个禁用项。
6. 知识库 demo 回退按当前作品隔离；新作品不得看到其他作品或默认演示文档。
7. Planning 样式懒加载，首屏 core + vendor gzip 目标不高于 40KB；构建断言和 CSS 级联审计必须同时通过。

## 8. 生图概念稿需求

- 用途：`ui-mockup`，仅作为桌面版 Planning / Cockpit 的视觉方向板，不作为像素级实现源。

- 文案：只使用 Yotsuba Ink 的阶段名和动作，不使用参考图品牌、任务编号、负责人或到期日。
- 风格：黑晶、银灰玻璃、克制的青绿活动色、精密排版；无品牌 Logo、无水印、无无关插画。
