# Phase 13：文学质量、作者控制与投稿准备度

> 状态：Phase 13.0、13.1、13.2A 与 13.2B 的 Detail 多场景契约切片已完成；逐场景 Provider 生成/恢复、冷编辑与真实 Provider 基线尚未完成
>
> 日期：2026-07-30
>
> 适用范围：正文上下文、Prompt 工程、章节生成、候选选择、质量评审、人工编辑、来源记录与投稿前检查
>
> 兼容基线：[阶段产物合同](./stage-artifact-contract.md) 是最高产品约束；本阶段不增加第八个创作阶段，不改变最终 `ChapterArtifact`、正式写回、恢复、封面并行和导出汇合语义。

## 1. 产品判断

Yotsuba Ink 下一步不能继续把“正文质量”理解为更多形容词、更多禁词或更长的单次 Prompt。当前系统已经较好地解决了结构、连续性、恢复和写回，但文学成稿仍缺少场景级意图、稳定的叙事视角、信息控制、冷编辑和真实人工偏好验证。

本阶段的核心目标是：

> 把已确认的 Story Brief、梗概、分卷与细纲编译成可执行的文学意图和场景合同，再通过纯正文起草、独立冷编辑、定点修订与章后事实抽取，稳定提高中文小说的可读性、独特性和作者可控性。

### 1.1 目标

1. 让前置 Artifact 约束真正进入每个场景，而不是只作为整章背景资料。
2. 让正文有稳定的叙事距离、感知过滤、句法节奏、词汇域、意象系统与潜台词策略。
3. 默认保持章节和分卷之间的行动、情绪、知识和空间连续性。
4. 让“意外”来自人物选择、信息揭示和行动后果，而不是随机反转或机械钩子。
5. 把生成与摘要、Wiki、人物和伏笔抽取分开，避免模型一边写文学正文一边填写后台表格。
6. 用盲化成对偏好、人工编辑行为和跨题材夹具验证改进，不再依赖单一模型自评分。
7. 为不同目标市场记录 AI 协作范围、规则检查日期和作者最终决策，形成可审计的投稿准备流程。

### 1.2 非目标

1. 不承诺“一键生成即可投稿”，也不以导出成功代表编辑完成。
2. 不以规避、欺骗或对抗 AI 检测器为目标，不将检测分数用于排序、门禁、Prompt 优化或产品宣传。
3. 不模仿在世作家的可识别文风，不提供“写得像某位作者”的内置模板。
4. 不抓取未授权小说全文作为风格样本；只允许用户自有、明确授权或公版文本。
5. 不新增“文学润色”阶段，不破坏现有七阶段导航。
6. 不把所有文学指标做成用户常驻面板；主界面仍以正文和作者决策为中心。

### 1.3 为什么不能以 AI 检测为目标

OpenAI 曾公开说明其文本分类器在挑战集上只识别出 26% 的 AI 文本，同时把 9% 的人类文本误判为 AI，并因准确率低而下线。检测器结果不能证明作者身份，也不能证明文学质量。

平台规则更不能由“检测通过”替代。晋江允许的 AI 辅助范围与番茄提供的 AI 写作工具明显不同；Apex 等投稿市场则明确拒绝 AI 辅助作品。产品必须保存目标市场规则和协作来源，而不是制造一个虚假的“可投稿”总分。

## 2. 当前能力与缺口

### 2.1 已具备的可靠基础

| 能力 | 当前实现证据 | Phase 13 处理 |
| --- | --- | --- |
| 阶段化约束 | Info -> Summary -> Outline -> Detail -> Text | 保留并增强编译过程 |
| 真实卷界 | `chapter_range`、卷目标、下一卷目标 | 保留 |
| 跨章承接 | 上一章摘要、上一卷结尾、转场指令 | 升级为 Context Packet v2 |
| 默认连续续写 | 只有细纲声明才允许 POV/时间跳切/倒叙 | 保留为硬约束 |
| 结构化正文产物 | 内容、摘要、Wiki、人物、伏笔、质量与版本 | 保留最终合同，拆分生成时机 |
| 稳定恢复 | `drafting`、`committing`、`completed` 检查点 | 保留外层十步事件 |
| 局部修订 | UTF-16 选区、候选预览、双签名与幂等接受 | 复用为定点修订执行器 |
| 质量复检 | 确定性检查、模型评审、修订方向 | 增加文学维度与评审隔离 |
| 正式写回 | 摘要、Wiki、人物、伏笔与 Canon 冲突 | 延后到正文定稿后的独立抽取 |

### 2.2 已确认的关键缺口

| 缺口 | 代码现状 | 风险 |
| --- | --- | --- |
| Voice 过粗 | 主要是人称、节奏、禁词、口头禅和语域 | 同一题材容易得到相似模板腔 |
| 整章直接扩写 | 细纲直接进入单次正文生成 | 场景转折、节奏与细节缺少中间控制 |
| 写作与抽取混合 | 同次调用返回正文、摘要和多类写回 | 模型注意力被后台结构分散，正文易解释化 |
| 候选评分失真 | `variant_score()` 奖励长度、关键词和候选序号 | 后生成或更长文本被错误选为“最佳” |
| 评审同源 | 生成与评审可落到同一 Provider/模型 | 自评偏差、共同盲点和风格趋同 |
| Voice 检测浅 | 词频、对话行比例、平均句长 | 无法判断叙事距离、感知过滤与潜台词 |
| 上下文裁剪失真 | 超限时 Voice 与人物层可整体丢弃 | 长篇后段最需要的声音和人物状态反而消失 |
| 承接材料不足 | 主要依赖上一章摘要 | 缺少结尾原文、未完成动作、情绪和知识余波 |
| Prompt 回归过窄 | 验证哈希、标题、字段与标记 | Prompt 稳定不等于成稿更好 |
| A/B 样本不足 | 只有少量模板差异案例 | 无法覆盖题材、视角、对话和复杂转场 |
| 人工质量信号缺失 | 没有盲评、偏好、编辑距离和首稿保留率 | 不能证明优化对作者有帮助 |
| 投稿语义缺失 | 没有目标市场与 AI 协作来源账本 | 容易把技术可导出误报为可投稿 |

## 3. 研究转译

### 3.1 长篇生成研究带来的工程结论

| 研究 | 可吸收结论 | 不直接照搬 |
| --- | --- | --- |
| Re3 | 规划、起草、检查和修订应分步；长篇不能只靠一次提示 | 英文故事指标不能直接当中文小说门禁 |
| DOC | 更细的层级大纲可减少长距离连贯错误 | 不能把更细大纲变成限制一切意外的剧本 |
| CritiCS | 多角色批评与计划修订优于单一自评 | 不为每章制造一组常驻“编辑 Agent”聊天面板 |
| DOME | 动态层级规划应随已写结果更新 | 不能让运行时重规划绕过已确认细纲和作者决定 |
| Character Simulation | 人物行动需要知识、动机与关系状态支持 | 角色模拟不能覆盖 Canon 或虚构未获得信息 |
| WritingBench | 评价标准应随任务与题材动态生成 | 动态 Rubric 仍需固定底线与人工校准 |
| LitBench | 成对偏好与人类标注比裸 LLM 打分更可靠 | 英文社区偏好不能代表中文投稿市场 |
| Wordcraft / Dramatron | AI 更适合进入可选择、可改写的人机共创流程 | 不把用户降级为仅负责点击确认的人 |

### 3.2 作家方法带来的产品结论

公开作家访谈反复指向四个共同点：

1. 初稿与成稿不是同一个产物。删改、重读和再次改写是写作的一部分。
2. 文风不是形容词列表，而是叙事立场、句法选择和具体细节的长期一致。
3. 细节必须被选择。把所有感官、背景和心理都写出来，只会形成没有形状的堆积。
4. 观点必须由人物经验、故事框架和行动后果承载，不能由旁白直接讲解主题。

因此，系统不应内置“卡尔维诺风格”或任何作家仿写按钮，而应把可迁移技法抽象为：

- 叙事距离与 POV 稳定性。
- 感知过滤与细节选择。
- 句法轮廓与段落呼吸。
- 词汇域和人物语域。
- 意象的出现、变形与回收。
- 对话中的目标、回避和潜台词。
- 信息隐藏、延迟解释和可回溯的惊奇。
- 冷却后重读、删减与定点重写。

## 4. Phase 13 质量模型

文学质量不能压成一个总分。系统采用五个并列维度，并保留证据与不确定性。

### 4.1 叙事质量

- 场景是否有可观察的行动、阻力、转折和代价。
- 开篇是否承接上一章真实余波，而非复述摘要。
- 信息揭示是否改变人物行动或读者判断。
- 场景切换是否有因果、时空或视角锚点。
- 章末是否由本章后果自然产生，而非机械悬念句。

### 4.2 人物质量

- 人物只使用其当前已知信息。
- 行动与欲望、恐惧、关系和处境一致，但允许有付出代价的变化。
- 对话各有目标与回避，不是所有角色共同解释剧情。
- 内心、语言和动作不重复表达同一情绪。
- 关系变化在后续场景中产生行为后果。

### 4.3 文体质量

- 叙事距离、感知过滤和时态稳定。
- 句法有题材与场景需要的变化，而非固定短句或整齐排比。
- 具体名词和动作承担表达，不依赖抽象情绪标签。
- 感官细节有 POV 选择性，不按视觉、听觉、嗅觉逐项打卡。
- 意象有演化，不是随机比喻和漂亮句子集合。
- 解释密度受控，允许留白、误解和未说出口的内容。

### 4.4 长篇质量

- 章节进入状态来自前章退出状态。
- 未完成动作、伤势、物品、知识差和情绪余波持续存在。
- 伏笔按状态推进，回收前不重复提醒。
- 卷首不重新开局，卷末结算卷目标并产生下一卷因果。
- 主题与意象随情节变化，不机械重复关键词。

### 4.5 作者与市场质量

- 作者能看到、修改和拒绝文学意图与修订建议。
- 文本保留用户选择后的独特偏好，不被全局“润色”抹平。
- 所用样本来源、模型调用、人工修改和最终定稿者可追溯。
- 目标市场规则已在投稿前由用户重新确认。
- “准备度”只描述检查结果，不承诺录用、签约或规则合规。

## 5. 正文内部 Artifact

这些是正文阶段内部子产物，不新增导航阶段；最终仍汇总为现有 `ChapterArtifact`。

### 5.1 `LiteraryIntent`

定义本章怎样被讲述，而不是本章发生什么。

```text
chapter
pov_character
narrative_person
narrative_distance
temporal_mode
sensory_filter[]
diction_domains[]
syntax_profile
paragraph_rhythm
image_system[]
subtext_strategy
disclosure_plan[]
emotional_turn
explanation_limits[]
originality_constraints[]
source_signatures[]
```

要求：

- `narrative_distance` 表达贴近意识、有限观察或更远叙述，不只写“第三人称”。
- `sensory_filter` 说明该 POV 会注意什么、忽略什么，必须来自职业、处境和情绪。
- `image_system` 只保留 1-3 个与故事相关的意象轨，不生成比喻清单。
- `explanation_limits` 明确哪些主题、背景和情绪不得直接讲明。
- `originality_constraints` 是对本项目自身重复模式的限制，不是 AI 检测特征。

### 5.2 `SceneContract`

把已确认细纲编译成可执行场景，不改变剧情决定。

```text
scene_id
chapter
order
location
time_anchor
pov_character
entry_state
visible_desire
obstacle
tactic
turn
cost
exit_state
withheld_information[]
knowledge_delta[]
relationship_delta[]
unresolved_action_in[]
unresolved_action_out[]
spatial_anchor[]
motif_touch[]
handoff_in
handoff_out
source_signatures[]
```

每个场景至少回答：谁想做什么、什么阻止了他、他换了什么办法、发生了什么不可逆变化、下一场景为什么必须发生。

### 5.3 `ProseDraft`

只负责文学正文，不在同次调用中生成摘要、Wiki、人物变化和伏笔字段。

```text
draft_id
chapter
scene_id
content
literary_intent_signature
scene_contract_signature
context_signature
provider_attempt
generation_metadata
```

### 5.4 `EditorialPass`

记录冷编辑发现和定点修订，不直接覆盖正文。

```text
pass_id
draft_id
editor_role
blind_label
findings[]
strengths_to_preserve[]
revision_targets[]
revised_draft_id
decision
```

`revision_targets[]` 必须包含证据、UTF-16 选区、修订目标、禁止破坏项和置信度。无法可靠定位时只能给方向，不能整章自动重写。

### 5.5 `SubmissionReadiness`

```text
market_profile_id
policy_url
policy_checked_at
ai_assistance_policy
format_requirements[]
rights_requirements[]
authorship_ledger_id
open_issues[]
author_acknowledgement
status
```

允许状态：`not_checked / incompatible / needs_author_review / ready_for_manual_submission_review`。禁止使用 `publishable`、`accepted` 或“保证过审”等状态。

## 6. Context Packet v2

### 6.1 新增字段

在现有卷目标、上一章摘要、人物状态、伏笔和世界规则之外增加：

```text
previous_chapter_tail
unresolved_actions[]
emotional_carryover[]
knowledge_delta[]
spatial_anchor[]
motif_state[]
relationship_pressure[]
injury_and_inventory_state[]
```

其中 `previous_chapter_tail` 保存上一章经确认的最后 600-1200 个中文字符，不能由摘要替代；它只用于下一章承接，不进入长期 Story Bible。

### 6.2 上下文优先级

上下文超限时不得整层删除 Voice 或人物状态。改为固定槽位和逐项压缩：

| 优先级 | 内容 | 超限策略 |
| --- | --- | --- |
| P0 | 输出合同、Canon 冲突、世界硬规则、当前 SceneContract | 不删除；超限即阻断 |
| P1 | 前章尾文、未完成动作、POV 知识、当前人物状态 | 结构化压缩，不整体删除 |
| P2 | LiteraryIntent、意象状态、关系压力 | 保留关键字段和来源签名 |
| P3 | 当前卷目标、伏笔、近期章节摘要 | 按相关性与时间衰减压缩 |
| P4 | 远期梗概、非当前人物、参考摘要 | 最先裁剪，可通过检索补回 |

### 6.3 上下文装配原则

- 每章、每场景只注入真正相关的人物、规则和伏笔。
- 摘要负责事实，尾文负责语气、动作和情绪承接，两者不可互相替代。
- 用户自有或授权样本只提取抽象 `Voice Genome`，默认不把大段原文送入正文调用。
- 每个上下文项带来源、版本和签名；不能确认来源的内容不进入硬约束。

## 7. Voice Genome

`Voice Spec` 保留为用户可理解的 Brief 字段；运行时编译为更细的 `Voice Genome`：

| 维度 | 示例语义 | 检查方式 |
| --- | --- | --- |
| 叙事距离 | 紧贴身体感受 / 保留观察距离 | POV 泄漏、心理访问范围、自由间接引语一致性 |
| 感知过滤 | 修复师先注意噪点、材质和机械误差 | 细节是否来自人物职业与当下目标 |
| 词汇域 | 技术词克制，情绪不直接命名 | 领域词分布、抽象情绪词密度 |
| 句法轮廓 | 压力时断裂，观察时延展 | 句长分布、从句结构和段落节奏，不只看平均值 |
| 意象系统 | 声音、潮汐、缺口逐章变形 | motif 状态与语义变化 |
| 对话策略 | 闪避、试探、权力差 | 目标、回避、潜台词与信息不对称 |
| 解释阈值 | 不直接解释母亲失踪带来的全部情绪 | 解释段、重复表达和总结句 |
| 禁止模式 | 本项目已高频出现的句式或动作 | 项目内重复与相邻段落相似度 |

不能把“短句为主”当成完整文风，也不能用全局同一个节奏覆盖追逐、审讯、亲密对话和静态观察。

## 8. 场景级生成流水线

### 8.1 总流程

```text
已确认 Detail Artifact
  -> Context Packet v2
  -> LiteraryIntent 编译
  -> 场景发散
  -> 约束选择与 SceneContract
  -> 逐场景 ProseDraft
  -> 场景接桥
  -> 冷编辑
  -> 定点修订
  -> 章节合同校验
  -> 章后摘要/事实/人物/伏笔抽取
  -> 现有 ChapterArtifact 与正式写回流程
```

### 8.2 场景发散

发散不是生成三份近义改写，而是产生 2-3 个结构差异明确的场景执行方案：

- 不同的角色策略。
- 不同的信息揭示顺序。
- 不同的代价落点。
- 不同的空间使用方式。
- 不同的意象触发方式。

所有方案必须满足已确认细纲；差异只存在于“如何实现”，不能偷偷改变“发生什么”。

### 8.3 约束选择

系统使用确定性合同先排除：

- 人物知道其不应知道的信息。
- 违背世界硬规则。
- 跳过上一场景未完成动作。
- 缺少可观察转折与代价。
- 重复近期章节的同类解决方式。

Balanced 可由隔离评审器做盲化成对选择；Deep 在章级别向用户展示真正不同的执行意图，不要求用户逐场景点确认。

### 8.4 纯正文落笔

正文调用只获得：当前 SceneContract、必要上下文、LiteraryIntent、上一场景尾文和输出字数区间。提示词不得要求同时解释质量、生成摘要或列出写回。

### 8.5 场景接桥

每个场景结束后保存：

- 实际退出状态。
- 未完成动作。
- 新增知识。
- 情绪余波。
- 空间位置和重要物件。
- 下一场景必须承接的 1-3 个具体锚点。

下一场景先消费实际结果，再消费原计划。实际正文没有发生的事不得写入上下文。

### 8.6 冷编辑

冷编辑使用新的无作者身份盲标签，只看正文、合同和必要证据，按顺序检查：

1. 是否有剧情、人物或 Canon 硬错误。
2. 是否存在解释替代行动、心理重复、对白讲解和无选择细节。
3. 是否存在项目内重复句式、相似场景解法和机械章末钩子。
4. 哪些独特句段必须保留，防止修订把文本磨平。
5. 哪些问题可定点修，哪些必须退回 SceneContract。

### 8.7 定点修订

- 一次修订只解决一个明确问题。
- 默认不重写整章。
- 修订 Prompt 同时携带“必须保留的强项”和选区外不可改变约束。
- 接受后继续复用现有版本、签名、预览和幂等合同。
- 超过两轮仍无法通过的结构问题回退场景合同，不继续无限润色。

### 8.8 章后抽取

正文稳定后，独立调用或确定性程序提取：

- 章节摘要。
- 新增事实与 Canon 候选。
- 人物状态和关系变化。
- 伏笔触发、推进与回收。
- 下一章 Context Packet v2。

抽取结果必须以最终正文为唯一事实源，并经过现有写回提案和签名校验。

## 9. 创新机制

“创新力”不能用随机温度替代。Phase 13 采用可审计的受约束发散机制。

### 9.1 新颖性预算

每章允许在以下维度选择 1-2 个创新点：行动策略、信息顺序、空间运用、意象变形、关系代价。其余维度保持稳定，避免每章都故意炫技。

### 9.2 可回溯的惊奇

反转必须同时满足：

1. 初读产生信息更新。
2. 回看能在前文找到充分但不显眼的依据。
3. 改变人物选择或关系，而不只是给读者一个答案。

### 9.3 信息隐藏与知识矩阵

为每个主要人物记录 `knows / suspects / believes / conceals / misreads`。正文生成只能从当前 POV 可感知的信息出发；潜台词来自“角色想达到什么”和“他不能说什么”的冲突。

### 9.4 意象账本

意象不是关键词计数。每次出现记录：对象、当前含义、人物关联、感情色彩和是否发生变形。重复出现但没有语义变化应被提示删减。

### 9.5 反模板审校

反模板审校检查作品内部的机械模式，不声称识别 AI：

- 开篇反复使用天气、醒来、环顾或自我介绍。
- 情绪先命名，再用动作和内心重复说明。
- 连续段落使用相同长度、三项排比或同构转折。
- 所有人物用同一种完整句解释信息。
- 每个场景都靠巧合、误听、突然发现或外部救援推进。
- 感官描写按固定清单出现，与 POV 目标无关。
- 章末固定使用抽象预示、格言或“他不知道的是”。
- 同一形容词、动作标签和比喻骨架跨章高频复用。

这些发现默认是编辑提示；只有合同、Canon、POV 知识和明确连续性错误可以硬阻断。

## 10. 模式合同

| 能力 | 极速 | 平衡 | 精细 |
| --- | --- | --- | --- |
| LiteraryIntent | 自动编译 | 自动编译 | 章级可查看和调整 |
| 场景发散 | 1 个方案 | 2 个盲化方案自动择优 | 2-3 个章级意图，用户可换稿 |
| 正文草稿 | 单稿 | 单稿；高风险章增加冷编辑 | 单稿；中高风险章增加冷编辑，完整候选只由用户主动换稿 |
| 模型评审 | 零模型审稿，仅确定性硬门 | 每章语义/衔接审稿，高风险双审串行 | 每章语义/衔接审稿，中高风险双审并行；只给证据，不替用户选择 |
| 人工闸门 | 不新增 | 不新增逐场景闸门 | 保持现有阶段/章节定稿语义 |
| 章后抽取 | 自动 | 自动 | 正文确认后生成写回提案 |

所有模式都受同一 Canon、连续性、来源和恢复合同约束；模式差异是控制权和成本，不是文学质量是否存在。

## 11. 评审与验证

### 11.1 评审器隔离

- 生成者与评审者配置独立的 Provider Profile、模型、Prompt 和缓存键。
- 评审器只看到随机盲标签，不看到候选序号、Provider、模型和生成顺序。
- 没有独立评审器时降级为确定性检查和人工选择，不伪装成客观文学评分。
- 评审器输出证据、偏好与置信度，不输出虚假的两位小数总分。

### 11.2 两层质量门禁

确定性硬门禁：

- 输出合同与签名。
- Canon 与世界规则冲突。
- POV 知识越权。
- 章节/场景进入退出状态断裂。
- 未注册人物、错误卷界和写回来源不一致。

编辑性软评审：

- 场景张力与转折。
- 叙事距离和感知过滤。
- 对话潜台词。
- 解释、重复与细节选择。
- 意象演化和项目内模板复用。

### 11.3 人工 A/B

每次 Prompt 或算法实验必须：

1. 对同一输入、同一上下文和可比预算生成基线/候选。
2. 隐藏版本名、模型名和生成顺序。
3. 让至少两名读者做成对偏好，不先看自动分数。
4. 分别评价“更愿意继续读”“人物更可信”“语言更有辨识度”“承接更自然”“更少需要重写”。
5. 记录分歧，不用简单平均掩盖题材偏好。

### 11.4 作者行为指标

核心成功指标：

- 首稿保留率：最终稿中保留的初稿字符比例。
- 必要编辑距离：达到作者可接受状态所需修改量。
- 结构返工率：是否频繁退回细纲或场景合同。
- 连续性修复率：跨章问题在定稿前被发现并修复的比例。
- 建议接受率：作者接受了哪些类型的修订建议。
- 时间与成本：每千字有效定稿所需时长、调用和费用。

这些指标只用于产品改进，不用于判定作者水平。

### 11.5 中文回归夹具

建立至少 24 个版权安全的自建中文案例，覆盖 6 个题材 x 4 类高风险场景：

| 题材 | 连续行动 | 强潜台词对话 | POV/时间转换 | 卷首/卷末 |
| --- | --- | --- | --- | --- |
| 悬疑 | 追踪物证 | 证人隐瞒 | 受控闪回 | 真相层级变化 |
| 都市情感 | 冲突余波 | 分手谈判 | 双视角切换 | 关系阶段结算 |
| 历史 | 仪式与行动 | 权力试探 | 时间跨度 | 局势与人物代价 |
| 科幻 | 规则下解题 | 知识不对称 | 空间/时间锚定 | 世界规则后果 |
| 奇幻 | 魔法代价 | 阵营交涉 | 多线汇合 | 任务结算与新因果 |
| 成长 | 技能失败 | 师徒分歧 | 内外目标错位 | 能力与价值选择 |

每个案例保存：上游 Artifact、Context Packet、基线正文、候选正文、人工偏好、编辑记录和失败原因。不得使用受版权保护小说原文作为金标。

## 12. 投稿准备与作者身份

### 12.1 `MarketProfile`

目标市场配置至少包含：

- 官方规则 URL。
- 最后人工复核日期。
- 允许、限制或禁止的 AI 协作范围。
- 字数、格式、首发、版权和同时投稿规则。
- 是否要求声明 AI 协作。
- 规则不明确时的联系或人工确认项。

规则可能随时变化，导出前必须重新检查；旧缓存不能自动给出“合规”。

### 12.2 `AuthorshipLedger`

记录：

- 用户提供的原始 Brief、细纲和自有文本。
- 每次模型生成的范围、时间、Provider/模型和 Prompt 版本。
- 用户选择、删除、改写和最终确认。
- 外部资料的 URL、许可与用途。
- 最终导出与 Artifact 签名。

该账本用于透明度、恢复和自证，不生成“纯人工”标签，也不能被用户一键伪造或删除来源。

### 12.3 投稿前检查

- `Export` 显示目标市场、规则复核时间和未决问题。
- 当目标市场明确禁止正文 AI 辅助时，系统标记 `incompatible`，不提供“检测降重”方案。
- 当规则允许有限辅助时，系统按账本指出超出范围的步骤。
- 没有目标市场时只显示通用编辑准备度，不声称可投稿。
- 最终投稿行为由用户在站外完成；v1 不做自动投稿。

## 13. 前端产品面

Phase 13 不把文学分析做成新的仪表盘。

### 13.1 正文工作台

- 正文继续占最大工作面。
- `LiteraryIntent` 进入当前章上下文的可折叠“叙述策略”，默认只显示 POV、距离、感知焦点和本章情绪转折。
- `SceneContract` 进入章节左栏的场景节拍，不与 Wiki、世界观和人物关系重复展示。
- 冷编辑结果进入现有质量 Inspector，按“硬错误 / 可定点修 / 建议保留”分组。
- 候选对比显示真正的执行差异和保留强项，不显示 Provider 或候选序号造成的暗示。
- 不新增持续动画、文学总分仪表、AI 概率或“投稿率”。

### 13.2 导出页

- 增加目标市场选择、规则复核、来源账本摘要和未决问题。
- 投稿准备度与导出文件生成分开：文件可以生成，但未决合规问题保持可见。
- 不把封面完成或章节齐全误报为投稿就绪。

## 14. 工程拆分

建议新增领域边界：

```text
src/novel_workflow/literary/
  schemas.py
  intent_compiler.py
  scene_compiler.py
  context_packet.py
  context_budget.py
  prose_generation.py
  editorial_pass.py
  pairwise_review.py
  anti_template.py
  authorship_ledger.py
  market_profiles.py
```

边界要求：

- `orchestration/chapters.py` 只编排步骤，不实现文学算法。
- `quality/engine.py` 只聚合检查，不新增大块规则。
- Prompt 文本与结构化 schema 分离；纯 helper 不留在 React 或路由文件。
- 每个模块保持单一职责，正常 200-250 行，重型模块不超过 300 行。
- 数据迁移提供兼容默认值；旧 Run 仍能打开、恢复和导出。

前端仅在真实后端字段落地后增加展示；禁止先画 `LiteraryIntent` 或 `SubmissionReadiness` 卡片，再用 Mock 假装已联通。

- 增加 Canon、POV 知识、未完成动作、世界硬规则和重复解法的确定性过滤。
- 按选定 SceneContract 逐场景生成、接桥并保存稳定点；恢复时不重写已完成场景。

本轮尚未达到完整退出条件。完整退出仍要求：最终 `ChapterArtifact` 不变；Fast/Balanced/Deep 行为符合模式合同；逐场景失败不重复生成、计费或写回；跨场景接桥以实际正文结果为事实源。

本轮自动化基线：后端 `319 passed / 1 skipped`；前端 `126 files / 496 passed`；生产构建、CSS 审计、首屏 CSS 拆分和 JSON 校验通过。未调用真实 Provider。

### Phase 13.3：冷编辑与定点修订

- 实现反模板、叙事距离、感知过滤、潜台词和意象检查。
- 生成者/编辑者职责隔离；保留强项与修订目标同时输出。
- 复用 UTF-16 选区、版本、签名与幂等接受。
- 正文稳定后再抽取摘要、Wiki、人物和伏笔。

退出条件：选区外文本逐字保持；整章自动重写有明确上限；抽取只基于最终正文。

### Phase 13.4：偏好评审与 Prompt 工程

- 删除 `variant_score()` 对候选序号的奖励。
- 引入盲化成对选择和独立评审配置。
- Rubric 由题材与场景动态补充，但保留固定硬门禁。
- Prompt 回归从哈希升级为结构、行为和成稿金丝雀测试。

退出条件：人工偏好显著优于基线，且编辑成本、调用成本和失败率没有不可接受上升。

### Phase 13.5：作者工作台与投稿准备

- 接通叙述策略、场景节拍、冷编辑证据与候选差异。
- 增加 MarketProfile、AuthorshipLedger 和导出前人工复核。
- 全部 UI 字段来自真实 Artifact；旧项目和 Demo 流程继续可用。

退出条件：用户能解释每条建议的证据和影响；目标市场不兼容时不会给出规避路径。

### Phase 13.6：真实 Provider 小流量验收

- 至少选择两个生成模型和一个隔离评审模型。
- 对 24 个夹具完成盲化人工评审，再跑一部多卷小样的完整链路。
- 验证暂停、恢复、失败、预算、版本、写回、封面并行和导出。
- 记录模型版本和日期，避免把一次结果当作长期能力。

退出条件：真实 Provider 证据完整；没有重复计费/写回；质量提升由人工偏好与编辑行为支持，不能只引用模型评分。

## 16. Definition of Done

Phase 13 只有同时满足以下条件才算完成：

1. 24 个以上跨题材中文夹具完成可重复基线与盲化 A/B。
2. 正文按场景合同生成，最终 `ChapterArtifact` 和七阶段合同保持兼容。
3. 上一章尾文、未完成动作、情绪、知识和空间余波进入下一章。
4. Voice/人物/P0-P1 上下文不再因字符预算被整层静默删除。
5. 正文生成与章后摘要、Wiki、人物和伏笔抽取分离。
6. 候选排序不再奖励候选序号或只看长度与关键词。
7. 生成者和评审者可隔离；评审盲化且提供正文证据。
8. 确定性硬门禁与编辑性软建议清楚分离。
9. 定点修订保留选区外正文，版本、签名、恢复和幂等测试通过。
10. 人工盲评、首稿保留率、编辑距离、成本和耗时均有可追溯报告。
11. 不存在 AI 检测优化、作家仿写、未授权语料和虚假“可投稿”承诺。
12. 目标市场规则、AI 协作范围、来源账本和最终作者确认可追溯。
13. 真实 Provider 的多章、多卷、暂停、恢复和写回链路通过。
14. 新模块满足仓库目录、职责和文件大小守则。

## 17. 研究局限

- 现有长篇生成研究以英文任务居多，只能提供流程启发，不能直接证明中文网文或文学投稿质量。
- LLM 评审在开放式写作中仍有偏好和模型家族偏差，必须由人工盲评校准。
- 平台规则会变化，本文记录的是研究日期所见规则，不能作为长期法律或投稿承诺。
- “AI 味”不是稳定、单一或可客观检测的属性；本文把它拆成可编辑的具体问题，例如解释过多、同构句法、人物同声和细节无选择。
- 在真实 Provider、足量中文样本和人工编辑数据完成前，不能宣称正文已经达到投稿水平。
