# Story Bible、Wiki、质量阀门与参考资料

## 为什么这个边界很重要

这些概念非常容易被混在一起，而一旦混在一起，长篇小说产品就会很难维护，也很难继续演进。

本仓库里正确的产品边界是下面这样：

## Story Bible / Wiki

角色定位：运行时事实层

它负责：

- 世界观硬设定
- 人物事实
- 关系变化
- 章节摘要
- 伏笔和连续性状态
- 与生成产物对应的写回记录

它不负责：

- 最终执行决策
- Provider 设置
- 通用知识库上传体验

## 质量阀门

角色定位：执行决策层

它负责：

- 问题是否阻断、是否可修订
- 质量分数和问题发现
- 修订指令
- 复检结果

它不负责：

- 规范世界事实的持久化
- 参考资料检索
- 阶段 prompt 的创作

## 参考资料

角色定位：外部 grounding 输入

它负责：

- 联网搜索结果
- URL 抽取后的上下文
- 合并后的参考摘要

它不负责：

- 连续性记忆
- 运行时事实写回
- 正文章节质量判断

## 知识库

角色定位：用户提供的 grounding 语料库

它负责：

- 用户上传文档
- 切块与检索
- 文档元数据

它不负责：

- 阶段执行
- 质量判断
- 正文章节连续性

## 产品判断规则

如果一个新功能说不清自己到底属于“事实记忆”“检索输入”还是“执行策略”，那它大概率就放错模块了，或者放错了 UI 面板。
