## 1. 本轮为什么不是继续打补丁

Phase 19-22 已经建立 Prompt Compiler、Detail v2、Reality Reconciliation、模式化 Reviewer、短章节奏和检查点恢复。Run F1 证明主体架构能够连续生成并提交前两章，但也暴露出四个仍会直接损害质量、成本或恢复正确性的交叉问题：

1. 重复检测器不能区分“无推进复写”和“同一物证从发现到公开传播的叙事复现”。
2. 检测器更新后，没有一条绑定冻结正文、Scene Draft 和检查点签名的零 Provider 重新校验路径。
3. 场景字符信封已经分成软节奏与硬安全两层，但 `max_tokens` 仍可能被验收配置当成逐场固定值，模型可在 1700 字目标下写到 3000 字以上。
4. 章级闭合容差已经被质量门认可，检查点总字数门却仍使用无容差总和，导致同一批正文在两个报告口径中一边通过、一边失败。

这些不是继续增加模型角色或 Prompt 清单能解决的问题。本轮只修正确定性控制层，并保持正文创作自由区不变。

## 3. Phase 23 实施合同

### 3.1 有语义作用的物证引语复现

重复豁免必须同时满足：

- 前后两段都是短、独立、完整包裹的直接引语；
- 后段是前段的包含、截短或高相似复现；
- 前段邻近上下文明确存在录音、声纹、缓存、硬盘、文件或扬声器等非现场证据载体；
- 后段邻近上下文明确存在播放、回放、广播、传出、循环或信号链等传播动作；
- 普通对白、叙述段落、动作链和场景开头复写不享受豁免。

豁免只改变 `scene_repetition` 的阻断结论，不把计划写成事实，不修改正文，也不影响场景边界动作重放检测。

### 3.2 零 Provider 确定性重新校验

恢复入口只接受当前 `quality_blocking`，并要求：

- 章节仍为 `prose_ready`；
- 当前整个 Chapter Artifact 与最后 `prose_ready` 检查点签名一致；
- Context Packet、Literary Intent、Scene Contract、Prose Draft、Scene Draft 和 Chapter Draft 逐项一致；
- 当前正文签名与请求签名一致；
- 没有当前章及下游章节的正式写回；
- 使用新检测器重算后不再存在阻断项；
- 只移除与当前 failure ID 匹配的活动错误和旧活动质量报告，历史事件与 `failure_history` 保留。

恢复事件必须声明 `provider_calls=0`、`generation_reused=true`、`budget_changed=false`、`formal_writeback=false`。它只把运行状态放回 `prose_ready` 的质量检查入口，不能直接跳过模型审稿、叙事抽取、Reality Reconciliation 或写回。

### 3.3 场景输出预算与 Token 上限

- `scene_generation_prompt_budget` 继续是字符信封权威。
- `scene_generation_max_tokens` 配置只作为上限，不再覆盖按当前场字符预算计算的上限。
- 正文生成按保守的 tokens-per-character 上界换算，并保留最小安全输出预算；修复、截断续写和结构化章后抽取使用各自既有预算，不共享这一上限。
- 这不是字符硬截断。Provider 若在 token 上限处截断，继续走现有“保存 partial -> 一次尾部续写/完整修复 -> 停靠”合同。
- 普通超出软范围仍只记录诊断；只有无法给后续场景预留最低空间或越过章级硬边界才触发一次修复。

### 3.4 验收字数口径

检查点总字数门必须继承已经由逐章事件证明的闭合容差。只有每章都满足普通区间或签名对应的闭合容差时，才允许总字数在这些章级容差之和内通过；不能用一个全局百分比掩盖单章失控。

2. 重复检测、输出预算、验收报告和零 Provider 恢复的定向回归。
3. 后端全量、Python `compileall`、运行时 Workflow/Prompt 镜像、`git diff --check`。
4. 前端全量、TypeScript、Vite build 和 CSS 审计只用于确认共享合同没有回归。
